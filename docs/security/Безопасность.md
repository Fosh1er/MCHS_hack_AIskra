# Безопасность АИскры (п. 6.2)

Документ для сопроводительной документации (7.2) и эксплуатации. Требования — ТЗ «Безопасность», 152-ФЗ; трассировка до кода и тестов — [specs/6.2-security.md](../../specs/6.2-security.md).

## 1. Контур и вход
- Снаружи доступен только nginx: `https://сервер:8443` (HTTP `:8080` перенаправляет на HTTPS). API, PostgreSQL и Ollama слушают только `127.0.0.1` сервера.
- TLS 1.2/1.3. Самоподписанный сертификат создаётся при первом старте контейнера `frontend` и хранится в томе `tls`. Свой сертификат: положите `server.crt` и `server.key` в том и перезапустите контейнер. Имя или IP сервера для самоподписанного — переменная `TLS_SAN`, например `DNS:aiskra.local,IP:10.0.0.5`.
- Браузер при первом входе покажет предупреждение о самоподписанном сертификате — это ожидаемо для локального контура; в сети учебного центра сертификат выпускается внутренним УЦ.

## 2. Учётные записи, сессии, права
| Мера | Реализация |
|---|---|
| Пароли | scrypt со случайной солью, длина 8–128; пароль не логируется и не возвращается |
| Подбор пароля | блокировка учётки после N неудачных попыток на 15 минут; дополнительно — не больше 20 неудачных входов с одного IP за 15 минут (429) |
| Сессия | случайный токен в cookie `HttpOnly`, `Secure` (под TLS), `SameSite=Strict`; в БД — только хеш токена; срок 24 ч; блокировка и смена пароля отзывают все сессии |
| CSRF | `SameSite=Strict` — браузер не отправляет cookie с чужих сайтов |
| Права | RBAC по правам, а не ролям; любой маршрут `/api/v1`, кроме входа, требует сессии — это проверяет автотест по всем маршрутам |
| Аудит | вход, выход, отказ в доступе, изменения пользователей, групп, настроек, карточек, оценок, копий — с IP и пользователем; журнал не редактируется |

JWT не используется: для одного сервера серверная сессия проще и отзывается мгновенно (ADR-0010).

## 3. Защита от инъекций и утечек
- **SQL:** только параметризованные запросы ORM; в служебном SQL имена таблиц экранируются.
- **XSS:** интерфейс не вставляет HTML из данных; CSP разрешает только собственные скрипты.
- **Встраивание, MIME, реферер:** `X-Frame-Options: SAMEORIGIN`, `frame-ancestors 'self'`, `nosniff`, `Referrer-Policy: same-origin`; HSTS под TLS.
- **Кеш:** ответы API помечены `Cache-Control: no-store`.
- **Загрузки:** тип файла — по содержимому (EXE под видом PDF отклоняется), размер до 25 МБ, имена файлов очищаются, файлы хранятся под случайным идентификатором.
- **Пути:** имена резервных копий — по строгому шаблону, материалы — по UUID; обход каталогов невозможен.
- **Ошибки:** на непредвиденную ошибку клиент получает «Внутренняя ошибка сервера», подробности — только в лог.
- **Открытый редирект:** после входа возврат только на внутренний путь.
- **ИИ:** пользовательский текст передаётся модели только как реплика пользователя, ответы — по JSON-схеме; внешние адреса моделей запрещены, пока администратор явно не разрешит `allow_external`.

## 4. Персональные данные (152-ФЗ)
- В учётке — только логин, ФИО, номер оператора. Паспортных и контактных данных система не хранит.
- Учебные данные синтетические: заявители, адреса вызовов из открытого справочника, телефоны заявителей — случайные учебные номера, телефоны служб — `+7 (495) 000-…`.
- В модели ИИ уходят легенды, реплики и учебные материалы — не данные учёток.
- Результаты обучения видят только сам обучающийся и преподаватели.

## 5. Журналы и сроки хранения
- Журнал аудита хранится не меньше 6 месяцев: срок — настройка «Хранение журнала» (от 183 до 3650 дней, по умолчанию 365). Записи старше срока удаляются командой или кнопкой; очистка сама пишется в аудит. Удалить отдельную запись нельзя.
- Регулярная очистка — cron на сервере:
  ```bash
  0 3 * * 0 docker compose exec -T backend python -m aiskra.cli purge-audit
  ```
- Резервные копии (5.2) включают журнал аудита.
