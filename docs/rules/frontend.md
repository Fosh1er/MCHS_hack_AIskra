# Правила frontend

- **UI только из `@smena112/ui-kit`** (токены, `.arm-*` для эмулятора АРМ, `.cab-*` для кабинетов). Новые цвета и шрифты не вводим. Если чего-то не хватает — компонент добавляется в ui-kit.
- **Карточка и реестр** повторяют АРМ заказчика (ADR-0008): раскладка, подписи, горячие клавиши. Учебные надстройки визуально отделены (полоса «ТРЕНАЖЁР», док справа).
- **Данные:** запросы — `useQuery`, команды — `useMutation` в `src/shared/api/<module>.ts`. Типы — из OpenAPI бэкенда (в будущем `openapi-typescript`).
- **Статус** = иконка + подпись + цвет, никогда не только цвет. Подписи из данных — только через JSX (никакого `dangerouslySetInnerHTML`).
- **АРМ** — десктоп (≥ 1366 px), клавиатура в первую очередь. Кабинеты — адаптивные до 375 px.
- **Тексты интерфейса** — по-русски.
- **Горячие клавиши АРМ** — через `pages/card112/useHotkeys.ts`: сравнение по `event.code` (не зависит от раскладки и от символов Option+буква на macOS), запасной вариант `keyCode()` — когда `code` пуст. Зажатый Alt показывает подсказки (`<Hint k="Alt+T" />` внутри блока с классом `arm112-rel`).
- **Сложная логика экрана — чистым редьюсером** без React (пример — `pages/card112/state.ts`): производные значения (конечный тип, признаки, службы) вычисляются функциями, а не хранятся в состоянии.
- **Размеры карточки 112** — токены UI-кита переопределены внутри `.arm112` по замерам стенда (снимки при 90 %). Новые размеры задавайте через эти токены, а не числами в компонентах.
- **Модальные окна карточки** — `.arm112-modalwrap` (затемнение `z-index: 0`, окно выше): иначе клик по кнопке попадает в затемнение.
