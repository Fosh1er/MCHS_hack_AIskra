# 0011. Голос собеседника: состояние на сервере, синтез за портом, распознавание начала речи в браузере

- **Статус:** Предложено · **Дата:** 2026-09-29 · **Пункты плана:** 3.6 (также 1.4, 2.3, 3.1, 3.3)

## Контекст
Команда просит перенести в АИскру голос из прототипа [emotional-stt-tts](https://github.com/zhamilka1/emotional-stt-tts). Прототип умеет три вещи:
- разговор «без рук» с перебиванием;
- эмоциональный синтез речи;
- звонящий, чьё состояние меняется от того, как с ним говорит оператор.

Разбор прототипа — в [исследовании](../research/Голос_и_эмоции_заявителя.md).

Прототип — отдельный сервис на Node.js. Вся логика у него в браузере, работает он только через внешний OpenRouter, лицензии нет. АИскра устроена иначе:
- модульный монолит на Python (ADR-0001);
- ИИ за портами с изолированным контуром по умолчанию (ADR-0003);
- легенда сценария не покидает сервер (R3.3-02);
- стенд под CSP `default-src 'self'`.

## Решение
1. **Переносим идеи, а не сервис.** Отдельный Node-сервис не поднимаем, код прототипа не копируем. Алгоритм и подобранные значения переписываем в существующие слои.
2. **Состояние собеседника — доменная сущность звонка на сервере.**
   - `CallerTone`: эмоция, напряжение, доверие, готовность отвечать, шкала 0–10. Темп, громкость, дыхание и перебивания выводятся функцией.
   - Начальное состояние — из сложности и группы происшествия.
   - Меняется детерминированными правилами по реплике оператора. Каждое срабатывание несёт код причины, чтобы преподаватель видел, что повлияло.
   - Снимок состояния сохраняется у каждой реплики собеседника — по нему синтезируется звук именно этой реплики.
   - Модель получает состояние в промпте, но **не меняет** его (до V5, где шаг модели ограничивается сервером).
3. **Синтез — адаптер `TTSPort` к OpenAI-совместимому `/audio/speech`.**
   - Эмоция передаётся структурно, в `VoiceProfile`. Адаптер переводит её в формат провайдера: `speech_metadata.style` для Google, `instructions` для OpenAI, только `speed` для Piper. **Текст реплики не смешивается с инструкцией.**
   - Внешний адрес — только при `allow_external`.
   - Кеш аудио — отдельный, с лимитом в мегабайтах.
4. **Звук — по запросу, отдельным ресурсом.**
   - `GET /training/calls/{id}/messages/{mid}/audio`, права — как на просмотр звонка.
   - Ответ на реплику остаётся текстовым и быстрым: текст виден сразу, звук догоняет.
   - Воспроизведение по адресу своего сайта, без `blob:`.
5. **Начало и конец речи оператора определяются в браузере (RMS, калибровка фона, гистерезис).**
   - Каждая фраза уходит в существующий `POST /training/speech`, потокового аудио на сервер нет.
   - Перебивание останавливает только звук. Реплики оператора ставятся в очередь, ответ модели не обрывается: реплики звонка — данные автооценки.
6. **Всё выключено по умолчанию.**
   - `tts.kind: fake` → озвучка браузером, темп, высота и громкость — по состоянию.
   - «Без рук» — переключатель. Кнопка «говорить» — режим по умолчанию.

## Отвергнутые варианты
| Вариант | Почему нет |
|---|---|
| Поднять прототип рядом (sidecar) и проксировать | Второй бэкенд без прав и аудита. Легенда уходит в браузер, модель выбирает клиент, работает только OpenRouter |
| Состояние в браузере, как в прототипе | Теряется при перезагрузке, не видно преподавателю и оценке, клиент может его подменить |
| Модель сама выставляет состояние (`TONE\|…`) | Бесплатные модели нестабильно держат формат. Реплика оператора попадает в модель, значит состояние можно «приказать» |
| Директива эмоции в тексте для синтеза | Модель без инструкций прочитает её вслух. Кеш по тексту смешает текст и стиль |
| Аудио внутри ответа на реплику (base64) | Ответ тяжелеет на 50–150 КБ и ждёт синтеза. Текст, по которому оператор заполняет карточку, приходит позже |
| Потоковое аудио на сервер (WebSocket, серверный VAD) | Новый транспорт и нагрузка на 6 ядер без GPU. Выигрыш — доли секунды |
| Silero TTS локально | Лучший открытый русский голос, но лицензия CC BY-NC для заказчика без разрешения не подходит |

## Последствия
**Плюсы:**
- эмоции работают и без модели, и без синтеза: правила в домене, озвучка — в браузере;
- преподаватель видит, как оператор повлиял на заявителя;
- в контуре заказчика тот же Speaches даёт и Whisper, и Piper.

**Минусы:**
- в изолированном контуре с Piper голос не передаёт эмоцию — только темп и слова;
- правила по фразам покрывают типовые формулировки, а не все;
- задержка «конец речи → звук» — 4–5 с на демо.

**Откат:** `TTS_KIND=fake`, переключатель «без рук» выключен. Колонки состояния в звонке не мешают старому коду: он их не читает.
