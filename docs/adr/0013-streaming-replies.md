# 0013. Потоковые ответы ИИ-собеседника

- **Статус:** Принято
- **Дата:** 2026-10-19
- **Пункты плана:** F1 (бэклог финала), 3.6 V5 (R3.6-31)

## Контекст
Ответ собеседника приходил целиком: оператор ждал всю генерацию и весь синтез. На медленной модели это 3–6 с тишины, а оператор 112 работает в нормативе 75 с. Нужно, чтобы ответ появлялся на экране по мере генерации и начинал звучать с первой фразы. При этом нужно сохранить то, что уже есть:
- проверку ответа модели психологическим профилем (`psy_render.validate`) и офлайн-замену;
- кеш ответов (ADR-0006);
- одну транзакцию на ход;
- работу без модели.

## Решение
- **Порт.** `LLMStreamPort.stream()` — необязательное расширение `LLMPort` (`ai/ports.py`):
  - адаптер без потока отвечает целиком, и `TaskModel.stream` отдаёт этот ответ одним куском;
  - OpenAI-совместимый адаптер читает SSE (`stream: true`);
  - кеш при попадании отдаёт сохранённый ответ по словам, при промахе собирает поток и кладёт в кеш только полный ответ.
- **Приёмник событий.** Логика хода не дублируется. `SendReplicaHandler`, `PsyDirector.turn` и `Actors` принимают необязательный `EventSink` (`training/application/events.py`) и сообщают через него о ходе:
  - `state` — состояние заявителя, известно до генерации;
  - `model` — ответ пишет модель;
  - `token` — кусок ответа;
  - `replace` — ответ модели отклонён проверкой или модель оборвалась.

  Без приёмника поведение прежнее.
- **HTTP.** `POST /training/calls/{id}/replicas/stream`:
  - обработчик работает в фоновой задаче со своей сессией БД (`StreamReplicaFactory`): сессия запроса закрывается раньше конца потока;
  - реплики одного звонка идут по очереди (блокировка на звонок);
  - обрыв соединения генерацию не отменяет: реплика сохраняется целиком, как и без потока;
  - ремарки `[плачет]` в поток текста не попадают и идут отдельным событием `remark`;
  - `final` несёт метрики: первый токен, полное время, скорость, источник ответа.
- **Озвучка по фразам.** `GET /training/calls/{id}/speak`:
  - фронт режет поток на предложения и сразу запрашивает звук каждого, воспроизводит по очереди;
  - подача голоса берётся из события `state`;
  - если ответ заменён, очередь сбрасывается и реплика звучит целиком.
- **Метрики честные.** Без модели подпись «ответ по правилам», имитации генерации нет.

## Последствия
- **Плюсы:** первая фраза звучит, пока модель ещё пишет. Один код хода для обычного и потокового ответа. Старый эндпоинт остаётся — для тестов, офлайна и отката (фронт переключается на него сам, если потока нет).
- **Минусы:**
  - ответ модели, который не прошёл проверку, оператор успевает увидеть до замены — помечено «заменяется»;
  - фоновые задачи и блокировки звонков держатся в памяти процесса — это допустимо для одного процесса (ADR-0005), а для нескольких реплик backend блокировку нужно перенести в БД;
  - метрики пока не сохраняются в `training_call_messages.meta.ai` (RF1-10, частично).
- **Откат:** фронт вызывает `POST /replicas`. Потоковый эндпоинт можно не публиковать: в nginx поток не буферизуется благодаря заголовку `X-Accel-Buffering: no`.
