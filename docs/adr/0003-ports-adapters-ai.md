# 0003. Порты и адаптеры для ИИ, маршрутизация задач по конфигу

- **Статус:** Принято · **Дата:** 2026-09-26 · **Пункты плана:** 0.1, 3.1

## Контекст
ТЗ: изолированный контур. Заказчик (#710, #746): на демо допустим внешний API, но адрес модели должен настраиваться, локальное развёртывание — обязательно. У заказчика нет GPU; разные задачи требуют разных моделей.

## Решение
- **Порты** `LLMPort`, `STTPort`, `TTSPort` (`aiskra/ai/ports.py`).
- **Адаптеры:**
  - `OpenAICompatibleLLM` — Ollama, vLLM, llama.cpp и внешние OpenAI-совместимые API;
  - `FakeLLM` — детерминированный, для офлайна и тестов;
  - `FakeTTS` / `FakeSTT`.
- **`ModelRouter.for_task(AITask.X)`** — задача → провайдер, температура, лимиты, кеш по `config/ai.yaml`. Код сценариев не знает модели.
- **`allow_external: false` по умолчанию.** Используемый провайдер с внешним адресом — ошибка конфигурации при старте. Разрешены localhost, частные сети и имена сервисов docker.
- **Структурированный вывод:** JSON Schema из pydantic-модели, одна попытка исправления при невалидном ответе.

## Последствия
- Смена модели или вынос её на GPU-сервер — правка конфига.
- Новый вендор — один класс-адаптер.
