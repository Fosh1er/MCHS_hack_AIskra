# 0015. Режимы окружения prod/demo/dev: безопасно по умолчанию, отказ запуска при небезопасных настройках

- **Статус:** Принято
- **Дата:** 2026-10-19
- **Пункты плана:** F6.3 (бэклог финала, дефект D1), F2 (демо-вход), 6.2 (безопасность)

## Контекст
Один и тот же образ работает в трёх местах:
- в контуре заказчика — закрытая сеть, реальные учётки;
- на публичном демо-стенде для экспертов — синтетические данные, вход в роль одной кнопкой (F2);
- у разработчика.

До F6 режим влиял только на демо-вход (F2). Остальное было одинаковым везде:
- Swagger открыт всем;
- cookie без `Secure` по умолчанию;
- пароль БД `aiskra` из `.env.example`;
- страница диагностики моделей жила по адресу `/dev/ai`.

Стенд при этом работал с `env: dev` (D1). Ошибку конфигурации контура заказчика можно было заметить только при аудите. Приложение запускалось и с паролем по умолчанию, и с внешней моделью, включённой одной строкой в YAML.

Ограничения:
- **ТЗ:** изолированный контур без внешних сетей (ответ #746). Swagger — часть поставки. Администратор следит за подсистемами и моделями.
- **Один образ** для всех режимов. Фронтенд собирается один раз и о режиме узнаёт из `/health`.
- **Демо и разработка не должны ломаться:** там удобство важнее строгости.

## Решение
Режим задаёт `AISKRA_APP_ENV` (`settings.app_env`):
- **prod** — значение по умолчанию в docker compose;
- **dev** — значение по умолчанию у `Settings`: локальный запуск и тесты.

| | prod — контур заказчика | demo — публичный стенд | dev — разработка |
|---|---|---|---|
| Демо-вход (F2) | маршрутов нет (404) | есть | есть |
| `/docs`, `/openapi.json` | только вошедшему администратору (`system.manage`): без входа — 401, другой роли — 403 и запись в аудит | открыты | открыты |
| `/dev/*` | нет ни в одном режиме (см. ниже) | — | — |
| Уровень логов | не подробнее INFO (`DEBUG` понижается до `INFO`) | как задан | как задан |
| Небезопасные настройки | **отказ запуска** со списком проблем | предупреждения в лог | предупреждения в лог |

**Проверка при запуске** — `platform/startup_checks.py:check_startup`. Её вызывают два места:
- `create_app`;
- команда `python -m aiskra.cli check-config`. В образе она стоит первой — до миграций и до `ensure-admin`. Так слабый пароль администратора не попадёт в БД раньше, чем запуск будет отклонён.

В prod проверка находит **все** проблемы сразу и останавливает процесс одним сообщением по-русски: код проблемы, что не так и какую переменную задать. Пример — в `specs/F6-prod-modes.md`. `uvicorn` выходит с кодом 1 без трассировки.

| Код | Условие отказа в prod | Как исправить |
|---|---|---|
| `cookie_insecure` | `AISKRA_SESSION_COOKIE_SECURE` не `true` | вход по HTTPS (в docker compose nginx с TLS — уже `true`) |
| `db_password` | пароль в `AISKRA_DATABASE_URL` пустой или известный (`aiskra`, `postgres`, `password`, `changeme`, `secret`); SQLite не проверяется | свой `POSTGRES_PASSWORD` в `.env` |
| `admin_password` | `AISKRA_BOOTSTRAP_ADMIN_PASSWORD` задан и слабый: из списка известных, совпадает с паролем демо-учёток, содержит логин, короче 12 символов или меньше 3 видов символов из 4 | сильный пароль |
| `external_ai` | в конфиге ИИ `allow_external: true`, а `AISKRA_AI_ALLOW_EXTERNAL` не `true` | явно задать переменную или выключить внешние модели |

**Переопределение — одно: `AISKRA_PROD_ALLOW_HTTP=true`.** Оно нужно для учебного контура в закрытой сети без TLS и разрешает только cookie без `Secure`. При каждом запуске в лог пишется предупреждение.

Пароли переопределением не обходятся. Сменить пароль можно всегда, законной причины оставить пароль по умолчанию нет. Внешние модели тоже не обходятся: для них есть собственная явная переменная, и ею служит та же `AISKRA_AI_ALLOW_EXTERNAL`, которую подставляют `config/ai.openrouter.yaml` и `ai.example.yaml`.

**`/dev/*` убран полностью.** Страница «ИИ-модели» переехала на `/admin/ai` и осталась только у администратора: на клиенте `RequireAuth system.manage`, на сервере `/api/v1/system/ai*` под `system.manage`, как и раньше. Почему не «выключить в prod»:
- в изолированном контуре администратору как раз нужно проверить, отвечает ли локальная модель. Это пробный запрос и назначение моделей на задачи. Без страницы этого не увидеть;
- серверная часть всегда была закрыта правом. Префикс `/dev` только создавал впечатление отладочного инструмента, который в проде не нужен;
- SPA одна для всех режимов. Прятать маршрут по режиму значит держать на клиенте вторую проверку того же права.

Поэтому в prod `/dev/*` нет вовсе, а диагностика — обычный раздел кабинета администратора.

**`/health`** отдаёт:
- `env` — режим;
- `version` — переменная `AISKRA_VERSION`, иначе `unknown`. Это короткий sha коммита: `ARG AISKRA_VERSION` в `backend/Dockerfile`, build-arg в docker compose, `make up` подставляет его сам;
- `started_at` — время старта процесса, UTC.

Внешний мониторинг (F6.7) по этим полям видит перезапуск и выкладку.

**Отклонение от техспеки F6.3.** Модель `fake` в `ai.default_provider` при включённых ИИ-функциях в prod **не** отклоняет запуск, а пишет в лог INFO «модели не подключены». Офлайн-режим — штатный режим контура по ТЗ: собеседники и генерация работают по легенде и шаблонам, ИИ-критерии помечаются «не проверено». Отказ запуска оставил бы контур без тренажёра там, где модели ещё нет.

## Последствия
- **Плюсы:**
  - ошибка конфигурации видна при первом запуске, а не при аудите;
  - prod по умолчанию закрыт: нет демо-входа, анонимного Swagger и `/dev`;
  - стенд и мониторинг видят режим и версию.
- **`docker compose up` на чистой машине с `.env.example` как есть не запустится.** Режим по умолчанию — `prod`, пароль БД — `aiskra`. Это намеренно. Для CI и smoke (F6.4) — `AISKRA_APP_ENV=demo` или свои пароли в `.env`. Для демо-стенда — `demo` (`docs/demo/Стенд_и_скринкаст.md`).
- **Администратор, созданный раньше со слабым паролем, не обнаруживается.** Проверяется только переменная окружения: хеш в БД сравнивать не с чем. Пароль меняют в «Пользователях».
- **Swagger UI грузит скрипты с CDN** (поведение FastAPI). В изолированном контуре страница `/docs` без интернета пустая. `/openapi.json` работает: схему можно открыть локальным инструментом.
- **`/health` публичен.** Короткий sha версии и режим раскрываются намеренно: это нужно внешнему мониторингу. Секретов в ответе нет.
- **Откат** — `AISKRA_APP_ENV=demo`: поведение до F6, но с предупреждениями в лог. Отдельного выключателя проверок в prod нет.
