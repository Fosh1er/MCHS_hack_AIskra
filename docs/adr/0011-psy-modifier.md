# 0011. Психологический модификатор сценария: детерминированная модель состояния заявителя и отдельный блок оценки

- **Статус:** Принято (реализовано в ветке `feat/3.6-psy-modifier`)
- **Дата:** 2026-09-27
- **Пункты плана:** 3.6 (новый), затрагивает 1.4, 2.3, 3.3, 3.4, 3.5, 4.1, 4.2, 4.3, 4.5

## Контекст
Сейчас эмоции заявителя задаёт одна строка `legend.emotion`. Её выбирает сложность 1–5, от «спокойно» до «в панике, путается в деталях». На эту строку опираются промпт ИИ-заявителя и первая реплика офлайн-легенды. Поведение оператора на неё не влияет: грубость и эмпатия дают один и тот же ответ, а автооценка работу с состоянием заявителя не проверяет.

Основания для доработки:
- профстандарт 12.002 (A/01) требует учитывать психологическое состояние заявителя;
- «Система 112» Москвы проверяет новичков ролевыми звонками с «неудобным» заявителем;
- ПП № 1931 вводит психологическую поддержку по телефону до 30 минут.

Источники — [docs/research/psychology](../research/psychology/00_README.md).

Ограничения:
- **Изолированный контур:** тренажёр работает без модели в офлайн-режиме, CPU без GPU (ADR-0003).
- **Воспроизводимость:** оценка должна повторяться при повторном прогоне (п. 3.5).
- **Выключаемость:** преподаватель проводит занятия и с модификатором, и без него. Без модификатора тренажёр ведёт себя байт-в-байт как сейчас.
- **Эталон не раскрывается:** ни заявителю, ни в промпте (R3.3-02).
- **Архитектура:** модули не импортируют друг друга (ADR-0001).

## Решение
1. **Модификатор ортогонален сценарию.** Психопрофиль (`psy_profile`) — отдельная сущность каталога `data/dictionaries/psy_profiles.yaml`. Он не меняет легенду, эталон карточки и эталон ДДС. Назначить профиль можно двумя способами:
   - закрепить за сценарием в банке — поле `scenarios.psy_profile`, значение необязательное;
   - задать правилом занятия — `settings.psy`: включён или нет, набор профилей, интенсивность.

   Итоговый профиль и seed записываются в звонок (`training_calls.psy`) при его создании. Звонок хранит снимок профиля, чтобы правка каталога не меняла прошедшие попытки.
2. **Состоянием управляет детерминированный движок, а не модель.** Модуль `training/domain/psy.py` описывает конечный автомат:
   - уровни возбуждения 1–5 по мотивам шкалы эмоционального состояния и готовности к сотрудничеству IAED (ECCS);
   - скалярные счётчики доверия и управляемости;
   - таблицу переходов по «действиям оператора» (`OperatorAct`).

   Действия оператора из реплики извлекает классификатор: офлайн — правила по словарям, как `topic_of`; с моделью — ИИ-задача `PSY_ACTS`, кеш `exact`. Текущий уровень определяет, какие факты легенды заявитель может раскрыть («ворота раскрытия»), и задаёт стиль реплики.
3. **Модель только «играет» заданное состояние.** Промпт `applicant_actor/v2.md` получает уровень состояния, описание речевого поведения и разрешённые темы. Модель возвращает текст с ремарками `[плачет]`, `[пауза]`, `[кричит]` по закрытому списку. Без модели работает офлайн-рендер: шаблоны профиля поверх `applicant_reply`.
4. **Голос — через существующий `TTSPort`.** `VoiceProfile` расширяется: темп, высота, громкость, эмоция, невербальные вставки, фон, телефонная полоса. Ремарки превращаются в параметры синтеза и звуковые вставки, из текста на экране они убираются. Движок синтеза выбирается конфигом `ai.tts`, как STT:
   - CPU по умолчанию;
   - GPU — вариант с управлением эмоциями.
5. **Отдельный блок оценки «Работа с заявителем» (`psy`).** Его критерии, веса и итог считаются отдельно от баллов 112 и ДДС:
   - контакт и контроль разговора;
   - применённые приёмы профиля;
   - запрещённые действия (критические);
   - траектория состояния;
   - время до адреса;
   - инструкции безопасности;
   - ИИ-судья эмпатии — «не проверено» без модели.

   По умолчанию блок в общий балл не входит и показывается рядом. Преподаватель может включить его в итог с весом (`settings.psy.weight`). Блок хранится в `assessments.details.psy` и версионируется вместе с оценкой.
6. **Безопасность обучающихся.** Профили «суицидальный абонент» и «ребёнок» помечены `sensitive`. Их выбирает только преподаватель. Обучающийся перед началом видит предупреждение, после звонка — разбор (debriefing).

## Последствия
- **Плюсы:**
  - воспроизводимость: одно и то же поведение оператора ведёт к той же траектории и той же оценке, офлайн и с моделью;
  - с выключенным модификатором кодовые пути не меняются, регрессия текущих тестов исключена;
  - каталог профилей правит методист, программист для этого не нужен;
  - на каждое состояние и приём оператора есть ссылка на источник.
- **Минусы:**
  - правила классификатора действий на ранних версиях будут грубыми, модель будет отставать от живого человека;
  - согласие блока с экспертом нужно измерять отдельно (п. 3.5);
  - эмоциональный TTS на CPU ограничен просодией (SSML), живой плач и крик требуют GPU или готовых звуковых вставок.
- **Откат:** выключить `settings.psy.enabled` по умолчанию. Миграция добавляет только необязательные JSON-столбцы.
