# 0001. Модульный монолит + чистая архитектура

- **Статус:** Принято · **Дата:** 2026-09-26 · **Пункты плана:** 0.1

## Контекст
Три дня до сдачи, команда 2–5 человек, объём — две учебные роли, ИИ, кабинеты. Жюри оценивает качество кода и интегрируемость. Нужна возможность параллельной работы и замены внешних компонентов (моделей, телефонии).

## Решение
- **Один backend-сервис**, разбитый на модули по предметным областям: `system`, `identity`, `dictionaries`, `incidents`, `training`, `assessment`, `audit`.
- **Слои внутри модуля:** `domain` (чистый Python) ← `application` (команды, запросы, порты) ← `infrastructure` и `api` (адаптеры).
- **Правила зависимостей проверяются автоматически** — `import-linter` в `make be-check` перед каждым коммитом (`backend/pyproject.toml`, `[tool.importlinter]`).

## Последствия
- Модули можно развивать параллельно; модуль при необходимости выносится в сервис по своей границе.
- Небольшие накладные расходы на структуру; смягчаются рецептами в `AGENTS.md`.
- Межмодульные вызовы запрещены по умолчанию. Если нужны — ADR и явное `ignore_imports`.
