# 0005. MVP в одном процессе

- **Статус:** Принято · **Дата:** 2026-09-26 · **Пункты плана:** 0.1, 6.1

## Контекст
ТЗ: ≤ 2 с при 100 пользователях, ≥ 20 сессий. Для MVP нагрузки класса (20–30 человек) один async-процесс обрабатывает с запасом. Узкое место — ИИ на CPU, а не API.

## Решение
- Один процесс uvicorn: REST + WebSocket. Таймеры и кеш — в памяти процесса.
- Redis, outbox, разделение на процессы `api` / `realtime` / `worker` — **после MVP**.
- ИИ никогда не стоит в синхронном пути интерфейса: реплики асинхронно, оценка после сохранения. Модели ограничены по CPU (`docker-compose.yml`) и по параллельности (`max_concurrency`).

## Последствия
- В документации («Условия и ограничения») фиксируем ограничение и путь масштабирования.
- Горизонтальное масштабирование потребует общей шины (Redis) — архитектура это допускает.
