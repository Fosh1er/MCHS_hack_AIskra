# Общие сведения

## Назначение

АИскра — учебный тренажёр оператора системы-112 и диспетчера дежурно-диспетчерской службы (ДДС). Администратор учебного центра отвечает за учебную среду:

- учётные записи, роли, блокировку и пароли;
- группы обучающихся с ролями на занятиях;
- состояние сервисов и оповещения о сбоях;
- настройки занятий по умолчанию, подсистем, IP-телефонии, журналирования и аудита;
- резервные копии и восстановление;
- логи процесса и журнал аудита;
- проверку ИИ-моделей и импорт справочников.

Установка и настройка сервера описаны в документе «Общее техническое описание» (`Общее_техническое_описание.pdf`).

## Рабочее место

- Браузер Google Chrome, Яндекс Браузер, Microsoft Edge или Firefox последней версии.
- Кабинет администратора работает на экране от 360 точек, журнал аудита удобнее смотреть на экране от 1280 точек.

## Права администратора

Каждое действие проверяется сервером по правам роли.

| Право | Администратор | Преподаватель | Обучающийся |
|---|---|---|---|
| Пользователи и группы | ✓ | чтение групп | — |
| Журнал аудита, настройки, резервные копии, импорт справочников | ✓ | — | — |
| Банк сценариев, занятия | — | ✓ | — |
| Учебные материалы | ✓ | ✓ | — |
| Чтение справочников | ✓ | ✓ | ✓ |

## Разделы кабинета

| Пункт меню | Адрес | Что в нём |
|---|---|---|
| Состояние | `/admin` | состояние сервисов, оповещения, импорт справочников |
| Пользователи | `/admin/users` | учётные записи и роли |
| Группы | `/admin/groups` | группы обучающихся |

| Аудит | `/admin/audit` | журнал аудита |
| Логи | `/admin/logs` | последние записи процесса |
| ИИ-модели | `/admin/ai` | назначение моделей и пробный запрос |

# Вход в систему

На демо-стенде у каждой роли на странице входа есть карточка с логином и паролем. Учётка администратора для проверки — `admin-demo`: она показана строкой под карточками, вход через форму по паролю демо-учёток.

Начальный администратор создаётся при первом запуске сервера: логин — переменная `AISKRA_BOOTSTRAP_ADMIN_LOGIN` (по умолчанию `admin`), пароль — `AISKRA_BOOTSTRAP_ADMIN_PASSWORD` в файле `.env`. В режиме prod пароль должен быть не короче 12 символов, содержать символы трёх видов из четырёх (строчные, прописные буквы, цифры, знаки) и не содержать логин, иначе сервер не запустится.

1. Откройте адрес тренажёра в браузере: `https://<сервер>:8443`.
2. Введите **логин** и **пароль**. Поле «номер АРМ» администратору заполнять не нужно.
3. Нажмите **ВОЙТИ**. Откроется раздел «Состояние».

Правила входа:

- после 5 неверных паролей подряд учётная запись закрывается для входа на 15 минут (`AISKRA_LOGIN_MAX_ATTEMPTS`, `AISKRA_LOGIN_LOCK_MINUTES`);
- с одного адреса — не больше 20 неудачных входов за 15 минут;
- сессия действует 24 часа (`AISKRA_SESSION_TTL_HOURS`), затем нужен повторный вход;
- в режиме demo кнопки входа в роль без пароля есть только у демо-учёток; администратор всегда входит по паролю.

После первого входа создайте учётные записи преподавателей и обучающихся.

# Пользователи

Раздел **Пользователи** — таблица учётных записей: ФИО, логин, роль, номер оператора, последний вход, статус. Над таблицей — поиск по логину или ФИО и фильтры по роли и статусу. На странице 50 записей, ниже — кнопки «назад» и «вперёд».

| Статус | Значение |
|---|---|
| активен | пользователь может войти |
| вход заблокирован | превышено число неверных паролей, вход временно закрыт |
| заблокирован | администратор заблокировал учётную запись |

## Создание пользователя

1. Нажмите **+ пользователь** в шапке раздела.
2. Заполните **Логин**, **ФИО**, **Роль**, при необходимости **Номер оператора**.
3. Введите **Пароль** — не короче 8 символов (не длиннее 128).
4. Нажмите **создать**. Кнопка недоступна, пока не заполнены логин, ФИО и пароль.

Роли: **обучающийся** (оператор 112 и диспетчер ДДС — одна учётная запись, учебную роль назначает группа или занятие), **преподаватель**, **администратор**.

## Изменение роли и данных

1. Нажмите на строку пользователя — под ней откроется редактор.
2. Измените **ФИО**, **Роль** или **Номер оператора**.
3. Нажмите **сохранить**.

Свою роль администратор изменить не может: поле недоступно. Изменение записывается в журнал аудита.

## Блокировка

1. Откройте строку пользователя.
2. Укажите **Причину блокировки** (необязательно).
3. Нажмите **заблокировать**.

Заблокированный пользователь не может войти, его открытые сессии завершаются. Чтобы вернуть доступ, нажмите **разблокировать**: заодно сбрасывается счётчик неверных паролей. Заблокировать себя нельзя.

## Сброс пароля

1. Откройте строку пользователя.
2. Введите **Новый пароль** — не короче 8 символов.
3. Нажмите **задать пароль**. Появится надпись «пароль задан, сессии пользователя завершены».

Новый пароль снимает и временную блокировку входа после неверных паролей.

# Группы

Группа — список обучающихся с ролью на занятиях. Преподаватель назначает занятие группой и видит группы только для чтения.

1. Откройте **Группы** и нажмите **+ группа** (или строку существующей группы).
2. Введите **Название**, не короче 2 символов, например «112-весна-1».
3. Отметьте обучающихся в таблице.
4. Для каждого выберите **Роль на занятиях**: «оператор 112» или «диспетчер ДДС».
5. Диспетчеру ДДС выберите **Службу**. Пока служба не выбрана, сохранить нельзя: внизу подсказка «укажите службу для ДДС».
6. Нажмите **сохранить**.

Кнопка **удалить группу** удаляет группу, учётные записи остаются.

# Состояние сервисов и оповещения

Раздел **Состояние** обновляется каждые 15 секунд и показывает плитки сервисов.

| Сервис | Что показано | Когда не в норме |
|---|---|---|
| База данных | СУБД, версия, пул соединений, отклик, число пользователей и карточек | отклик от 200 мс — предупреждение; нет подключения — сбой «БД недоступна» |
| ИИ-модели | провайдер и модель каждой задачи | задачи в офлайн-режиме (провайдер `fake`) — предупреждение |
| Кеш ИИ | доля попаданий, число записей | — |
| Телефония | режим «встроенная имитация», озвучка (сервер или синтез речи браузера), SIP «не подключён» | — |
| Резервные копии | число копий, возраст последней, свободное место на диске | копий нет или последней больше 24 часов — предупреждение |

**Оповещения** — баннер над плитками и счётчик на пункте меню «Состояние». В них попадают сервисы с предупреждением или сбоем и ошибки в логе приложения за последний час; от 10 ошибок оповещение становится критическим. Панель опрашивает оповещения раз в 30 секунд.

Если бэкенд недоступен, в разделе появляется баннер «Бэкенд недоступен».

# Настройки

Раздел **Настройки и копии**. Каждый блок сохраняется своей кнопкой **сохранить**; **отменить** возвращает сохранённые значения. Значение вне допустимого диапазона сервер не примет и покажет границы. Каждое изменение записывается в журнал аудита: что было и что стало.

## Занятие по умолчанию

Значения подставляются в новое занятие; преподаватель может их изменить.

| Параметр | По умолчанию | Диапазон |
|---|---|---|
| Норматив карточки 112, с | 75 | 5–3600 |
| Норматив решения ДДС, с | 30 | 5–3600 |
| Порог «зачтено», балл | 70 | 0–100 |
| Сложность вызовов | 2 | 1–5 |
| Темп вызовов 112, с | 40 | 5–3600 |
| Темп карточек ДДС, с | 45 | 5–3600 |
| Очередь ДДС, не больше | 3 | 1–10 |

## Хранение копий и ежедневная копия

| Параметр | По умолчанию | Диапазон |
|---|---|---|
| Хранить копий | 10 | 1–100 |
| Ежедневная копия: 1 — включена, 0 — нет | 1 | 0–1 |
| Час ежедневной копии (МСК) | 3 | 0–23 |

Ежедневную копию делает встроенный планировщик в заданный час по Москве. Если сервер был выключен в этот час, копия создаётся при первом запуске в те же сутки. В аудите она записывается от имени системы. Сверх заданного числа хранятся только последние копии.

## Запуск и остановка подсистем

Блок «Сервисы тренажёра: запуск и остановка».

| Параметр | 1 | 0 |
|---|---|---|
| Поток учебных вызовов 112 | работает | остановлен |
| Выдача карточек в очередь ДДС | работает | остановлена |
| Роль оператора 112 (по умолчанию 0) | включена: журнал и карточка 112, учётки операторов на входе, занятия с ролью 112 | скрыта: приоритет — диспетчер ДДС, обучающийся попадает в АРМ ДДС |

## IP-телефония

Встроенный софтфон тренажёра: входящие 112, звонки ДДС, удержание. SIP-шлюз не подключён.

| Параметр | По умолчанию | Диапазон |
|---|---|---|
| Удержание: заявитель ждёт не дольше, с | 60 | 10–600 |

Когда время удержания истекает, учебный заявитель кладёт трубку.

## Журналирование

Уровень журнала процесса применяется сразу, без перезапуска. Записи видны в разделе «Логи».

| Значение | Что пишется |
|---|---|
| DEBUG | подробно |
| INFO | обычный режим, по умолчанию |
| WARNING | предупреждения |
| ERROR | ошибки |
| CRITICAL | только сбои |

## Аудит: срок хранения

| Параметр | По умолчанию | Диапазон |
|---|---|---|
| Срок хранения журнала аудита, дней | 365 | 183–3650 |

Срок не может быть меньше 6 месяцев. Блок **Очистка журнала аудита** удаляет только записи старше срока:

- **сколько будет удалено** — проверка без удаления;
- **очистить** — удаление после подтверждения. Сама очистка записывается в аудит.

То же из командной строки: `docker compose exec backend python -m aiskra.cli purge-audit`.

# Резервные копии и восстановление

## Что входит в копию

Копия — сжатый JSON рабочих данных: пользователи, группы, сценарии, занятия, карточки, оценки, журнал аудита, настройки. Справочники в копию не входят, их восстанавливают импортом (раздел 10). Файлы учебных материалов хранятся в томе `materials`.

## Создание и скачивание

1. В блоке **Резервные копии** нажмите **создать копию**.
2. Появится строка «Копия <имя>: таблиц N, строк M».
3. Кнопка **скачать** в строке копии сохраняет файл на компьютер.

Полная копия базы PostgreSQL средствами СУБД: `docker compose exec db pg_dump -U aiskra aiskra > backup.sql`.

## Восстановление

1. Нажмите **восстановить** в строке нужной копии.
2. Прочитайте предупреждение: рабочие данные заменятся состоянием копии, всё созданное после неё пропадёт, все пользователи выйдут из системы.
3. Введите слово **ВОССТАНОВИТЬ** и нажмите **восстановить**.

После восстановления все сессии завершены, войдите заново. Событие записывается в журнал аудита. **Отмена** закрывает форму без изменений.

# Логи

Раздел **Логи** — последние записи процесса: время, уровень, источник, сообщение. Обновляется каждые 10 секунд.

- Фильтр уровня: **все**, **предупреждения**, **ошибки**.
- Поле **поиск по тексту** отбирает записи по фрагменту сообщения.

Что попадает в лог, задаёт уровень журналирования (раздел 6.5). Журнал контейнеров целиком — `docker compose logs`.

# Журнал аудита

Раздел **Аудит** оформлен как журнал АРМ-112. В журнал пишутся: вход, выход, отказ в доступе, изменения пользователей, групп, настроек, карточек, оценок, резервных копий — с пользователем и адресом. Записи не редактируются; удалить их можно только очисткой старше срока хранения.

Поиск:

1. Введите текст в **Поиск события** и при необходимости выберите **Тип события**.
2. Отметьте, где искать: **по оператору**, **по карточке**.
3. Задайте период **Искать по датам**. По умолчанию — со вчерашних 00:00 до сегодняшних 23:59.
4. Нажмите **искать**.

| Колонка | Содержание |
|---|---|
| Карточка | номер карточки 112, если событие к ней относится |
| Опер. | номер оператора |
| ФИО оператора | кто выполнил действие; «Система» — действие сервера |
| Дата, Время | когда |
| Событие | тип события |
| Описание | подробности; номер АРМ, если есть |

IP-адрес события виден во всплывающей подсказке строки. Внизу — выбор страницы и числа записей на странице: 15, 30, 50 или 100.

# ИИ-модели

Раздел **ИИ-модели** показывает, какие модели работают, и проверяет их. Модели и ключи настраиваются в файле `config/ai.yaml` и переменных окружения, в интерфейсе — только просмотр.

| Блок | Что показывает |
|---|---|
| Состояние | API, база данных, доля попаданий в кеш ИИ, режим (prod, demo, dev) и версия |
| Назначение моделей на задачи | для каждой задачи — провайдер, модель, температура, режим кеша; в подзаголовке — разрешены ли внешние адреса |

**Пробный запрос:**

1. Выберите задачу, например `probe`.
2. Введите текст запроса или оставьте предложенный: «Скажи «готов», если слышишь меня».
3. Нажмите **Отправить**.

Ответ показывает провайдера, модель, текст, время ответа в миллисекундах и источник: «от модели» или «из кеша». Ошибка выводится красной плашкой.

Провайдер `fake` — офлайн-режим: собеседники и генерация работают по правилам, без модели, занятие не прерывается. Краткая таблица моделей есть и в разделе «Настройки и копии» → «Модели ИИ».

# Импорт справочников

Блок **Импорт справочников** в разделе «Состояние» загружает данные из каталога `data/` сервера.

| Кнопка | Что загружается |
|---|---|
| классификатор и справочники | классификатор происшествий, службы, территория, перечисления, бригады |
| адреса и районы | адресный справочник и границы районов (OpenStreetMap) |

После импорта показываются файл, число записей по каждому справочнику и предупреждения (первые 5). Импорт нужен после установки и после восстановления из резервной копии.

Из командной строки:

- `docker compose exec backend python -m aiskra.cli import-dictionaries`
- `docker compose exec backend python -m aiskra.cli import-addresses`

# Частые вопросы

| Ситуация | Что сделать |
|---|---|
| Пользователь забыл пароль | **Пользователи** → строка → **Новый пароль** → **задать пароль** |
| Статус «вход заблокирован» | подождать 15 минут или задать новый пароль |
| Плитка «ИИ-модели» жёлтая | модели не подключены, работает офлайн-режим; подключение — `config/ai.yaml` |
| Плитка «Резервные копии» жёлтая | копий нет или последней больше суток — **создать копию**, проверить ежедневную копию в настройках |
| Нужно остановить поток вызовов | «Сервисы тренажёра» → поток учебных вызовов 112 = 0 → **сохранить** |
| Кто изменил настройку | **Аудит** → тип события «Изменение настроек», нужный период |
