# Назначение

АИскра — учебный тренажёр для практического обучения операторов системы-112 и диспетчеров дежурно-диспетчерских служб (ДДС). Обучающиеся работают в интерфейсе, воспроизводящем АРМ-112 и АРМ ДДС, в компьютерном классе учебного центра или удалённо под контролем преподавателя. Заявителей, старших групп и диспетчеров других служб играет искусственный интеллект. Работу обучающегося система оценивает по эталону сценария.

Границы применения:

- учебная система: реальные вызовы не принимаются, функции реальной системы-112 не реализуются;
- работа в изолированном контуре учебного центра; внешний API языковой модели допускается только на демонстрационном стенде по явному разрешению;
- учебные данные синтетические: заявители, телефоны, легенды генерируются; адреса — из открытого справочника OpenStreetMap.

# Функции и возможности

## Администратор

- учётные записи: создание, роль, блокировка, сброс пароля;
- группы обучающихся с ролью на занятиях и службой ДДС;
- состояние сервисов (БД, ИИ-модели, кеш ИИ, телефония, резервные копии) и оповещения о сбоях;
- настройки: занятие по умолчанию, хранение копий и ежедневная копия, запуск и остановка подсистем, удержание звонка, уровень журнала (сразу, без перезапуска), срок хранения аудита;
- резервные копии: создание, скачивание, восстановление;
- логи процесса, журнал аудита, проверка ИИ-моделей пробным запросом, импорт справочников.

Подробно — `Руководство_администратора.pdf`.

## Преподаватель

- банк сценариев: генерация по категориям классификатора и сложности, легенда и эталон, прогон вопросов и ответов, правка, перегенерация по комментарию, полное или частичное утверждение;
- ветвящиеся сценарии: итог ситуации зависит от решений оператора;
- психологический модификатор: заявитель в стрессе (15 профилей) с отдельной оценкой «Работа с заявителем»;
- занятия группой (112, ДДС, смешанные) с темпом вызовов и карточек, мониторинг в реальном времени;
- отчёт по занятию: автооценка по эталону, экспертная правка, тепловая карта, CSV и PDF; отзыв обучающемуся с черновиком от ИИ;
- аналитика, готовность к допуску, учебные материалы (PDF, DOCX, XLSX, TXT).

Подробно — `Руководство_пользователя_Преподаватель.pdf`.

## Обучаемый: оператор 112

- журнал происшествий и карточка 112 как в АРМ-112;
- учебный входящий вызов с ИИ-заявителем: текстом, голосом или без рук; удержание;
- адрес со справочником и картой, опросная карта классификатора, автоподбор служб;
- сохранение, отработки, «отработана», дополнение карточки, связь повторных обращений;
- свои результаты с разбором ошибок, рекомендации, отзывы преподавателя, справочная база.

## Обучаемый: диспетчер ДДС

- выбор службы; на занятии доступна только назначенная служба;
- журнал карточек службы с таймерами ожидания и сигналом о новой карточке;
- решение «Принята / Не принята», статусы до «Работы завершены», номер наряда, выбор бригад;
- IP-телефон: старший группы, заявитель, диспетчеры других служб; журнал звонков.

Подробно для обеих ролей обучаемого — `Руководство_пользователя_Обучающийся.pdf`.

## ИИ-модуль

| Задача | Что делает |
|---|---|
| Генерация сценария | легенда и эталон по типу классификатора и сложности |
| ИИ-собеседники | заявитель (с эмоцией и психологическим профилем), старший группы, диспетчер другой службы |
| ИИ-судья | смысловые критерии оценки карточки и работы ДДС |
| Инсайты и черновик отзыва | выводы по группе, черновик отзыва преподавателя |
| Речь | синтез речи реплик (сервер или браузер), распознавание речи оператора |

Модель используется только там, где нужен естественный язык; тип происшествия, службы, адрес, статусы и баллы вычисляются правилами. Без модели система работает в офлайн-режиме: собеседники отвечают по легенде, оценка — по правилам, смысловые критерии судьи — «не проверено». Занятие не прерывается.

# Состав и архитектура

| Компонент | Технология | Назначение |
|---|---|---|
| Клиент | React 18, TypeScript, Vite | одностраничное приложение: эмуляторы АРМ, кабинеты ролей |
| Вход | nginx 1.27 | TLS 1.2/1.3, перенаправление HTTP на HTTPS, статика, заголовки безопасности, прокси API |
| Сервер приложений | Python 3.12+, FastAPI, SQLAlchemy 2 | API `/api/v1`, бизнес-логика, ИИ-слой; один процесс |
| База данных | PostgreSQL 16 | все данные; для демонстрации и тестов — SQLite |
| Языковая модель | OpenAI-совместимый сервер: Ollama, vLLM, llama.cpp | профиль `local-llm` в docker compose |
| Телефония | встроенный IP-телефон в браузере | имитация звонков; SIP-шлюз не подключён |

Сервер — модульный монолит: модули identity, dictionaries, incidents, training, assessment, audit, system. Модули связаны через порты и адаптеры, правила проверяются автоматически.

```
Браузер ── HTTPS :8443 (HTTP :8080 → HTTPS) ──► nginx ──► backend :8000 (127.0.0.1)
                                                            ├─► PostgreSQL :5432 (127.0.0.1)
                                                            └─► Ollama :11434 (127.0.0.1, профиль local-llm)
Тома: pgdata, backups, materials, tls, ollama
```

Подробно — `docs/delivery/out/Пояснительная_записка_АИскра.pdf`.

# Порядок монтажа (установки)

## Требования к серверу и клиентам

| Параметр | Значение |
|---|---|
| Сервер | 6 ядер, 32 ГБ ОЗУ, NVMe 512 ГБ; GPU не требуется |
| ОС сервера | Linux с Docker 24+ и docker compose v2 |
| Открытые порты | 8080 (HTTP, перенаправление) и 8443 (HTTPS); 8000, 5432, 11434 — только 127.0.0.1 |
| Клиенты | Windows 10/11, Ubuntu 20.04+; актуальные Chrome, Firefox, Яндекс Браузер |
| Экран | эмулятор АРМ — от 1024 точек по ширине; кабинеты — от 360 точек |
| Микрофон | для голосового ввода; работает только по HTTPS или на localhost |

## Установка через docker compose

1. Получить исходный код из репозитория.
2. Создать файл окружения: `cp .env.example .env`.
3. В `.env` задать `POSTGRES_PASSWORD` (свой, без символов `@ : / ? #`) и `AISKRA_BOOTSTRAP_ADMIN_PASSWORD` (в prod — от 12 символов, 3 вида символов из 4, без логина).
4. Проверить настройки заранее: `docker compose run --rm backend python -m aiskra.cli check-config`.
5. Собрать и запустить: `docker compose up --build -d` (или `make up` — версия коммита попадёт в `/health`). При старте применяются миграции и создаётся администратор.
6. Указать имя или IP сервера для сертификата: `TLS_SAN=DNS:aiskra.local,IP:10.0.0.5` в `.env`. Свой сертификат — файлы `server.crt` и `server.key` в томе `tls`.
7. Открыть `https://<сервер>:8443`, войти администратором.
8. Загрузить справочники: кнопками в разделе «Состояние» или командами `import-dictionaries` и `import-addresses`.
9. Для учебного стенда с данными: `AISKRA_DEMO_PASSWORD=<пароль> make demo-seed-docker` — справочники, адреса, 30 утверждённых сценариев, учётные записи преподавателя и обучающихся, группа.
10. Локальная модель (по желанию): `docker compose --profile local-llm up -d`, затем `docker compose exec ollama ollama pull qwen2.5:7b-instruct`.

Сервисы перезапускаются автоматически и имеют проверку работоспособности `/health`.

## Стенд на своём компьютере

Демонстрационный стенд без Docker — скрипт `tools/stand/stand` (macOS): backend, собранный фронтенд и веб-сервер Caddy, который сам получает сертификат Let's Encrypt.

| Шаг | Действие |
|---|---|
| Установка | `brew install caddy uv node`, `make be-install && make fe-install` |
| Сеть | статический внешний IP; проброс TCP 80 и 443 на компьютер; записи A домена на внешний IP |
| Настройки | `tools/stand/stand init` — файл `~/aiskra-stand/stand.env` (домены, пароли) и база с демо-данными |
| Запуск | `stand up`; без домена — `stand up --local` (локальный сертификат) |
| Контроль | `stand status`, `stand logs`, `stand logs caddy`; остановка — `stand down` |

Подробно — `docs/demo/Стенд_на_своём_компьютере.md`.

# Настройка функционирования

## Режимы работы

Режим задаёт переменная `AISKRA_APP_ENV`; docker compose по умолчанию — `prod`.

| | prod | demo | dev |
|---|---|---|---|
| Назначение | контур учебного центра | публичный демо-стенд | разработка |
| Небезопасные настройки | запуск отклоняется | предупреждение в лог | предупреждение в лог |
| Вход в роль без пароля | нет | демо-учётки | демо-учётки |
| Swagger `/docs` | только администратору | доступен | доступен |

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `AISKRA_APP_ENV` | режим: prod, demo, dev |
| `POSTGRES_PASSWORD` | пароль БД; docker compose подставляет его в `AISKRA_DATABASE_URL` |
| `AISKRA_BOOTSTRAP_ADMIN_LOGIN`, `AISKRA_BOOTSTRAP_ADMIN_PASSWORD` | начальный администратор |
| `AISKRA_SESSION_COOKIE_SECURE` | cookie сессии только по HTTPS; в docker compose — `true` |
| `AISKRA_PROD_ALLOW_HTTP` | prod без TLS в закрытой сети; cookie без Secure |
| `AISKRA_SESSION_TTL_HOURS`, `AISKRA_LOGIN_MAX_ATTEMPTS`, `AISKRA_LOGIN_LOCK_MINUTES` | срок сессии (24 ч), попытки входа (5), блокировка (15 мин) |
| `AISKRA_AI_CONFIG` | файл конфига ИИ в `config/`, по умолчанию `ai.yaml` |
| `AISKRA_AI_ALLOW_EXTERNAL` | явное разрешение внешних адресов моделей |
| `LOCAL_LLM_URL`, `LOCAL_LLM_MODEL`, `DEMO_LLM_URL`, `DEMO_LLM_MODEL`, `DEMO_LLM_API_KEY` | адреса и модели; ключи — только в окружении |
| `TTS_*`, `STT_*` | серверный синтез и распознавание речи |
| `AISKRA_DEMO_PASSWORD` | пароль демо-учёток для `demo-seed` |
| `TLS_SAN` | имена и адреса сервера в самоподписанном сертификате |

## Конфигурация ИИ: config/ai.yaml

- `providers` — модели: `fake` (офлайн) или `openai_compatible` с `base_url`, `model`, `timeout_s`, `max_concurrency`; ключ — имя переменной в `api_key_env`.
- `tasks` — назначение провайдера каждой задаче: температура, режим кеша (`exact`, `task`, `off`), версия промпта.
- `allow_external: false` — разрешены только localhost, частные сети и имена сервисов docker compose; внешний адрес при старте — ошибка конфигурации.
- `tts`, `stt` — серверный синтез и распознавание речи; по умолчанию выключены (`fake`).
- Поставляемый `config/ai.yaml` — полностью офлайн. Пример локальной и внешней модели — `config/ai.example.yaml`, демо-стенд — `config/ai.openrouter.yaml`.
- Для сервера без GPU: `qwen2.5:7b-instruct` для генерации и судьи, `qwen2.5:3b-instruct` для реплик, не больше двух параллельных генераций.

Проверка: кабинет администратора → «ИИ-модели» → пробный запрос.

## TLS

- nginx при первом запуске создаёт самоподписанный сертификат на 825 дней для `localhost`, `127.0.0.1` и имён из `TLS_SAN`.
- Если в томе `tls` есть `server.crt` и `server.key`, используется он.
- HTTP :8080 перенаправляет на HTTPS :8443.

## Резервное копирование

- Ежедневная копия — встроенный планировщик, час по Москве задаётся в настройках; число хранимых копий — там же.
- Копии лежат в томе `backups`; свободное место на диске показывает плитка «Резервные копии».
- Полная копия PostgreSQL: `docker compose exec db pg_dump -U aiskra aiskra > backup.sql`.
- Журнал аудита хранится не меньше 183 дней; очистка — `docker compose exec backend python -m aiskra.cli purge-audit`.

# Возможные неисправности и их устранение

## Запуск сервера

В режиме prod сервер не запускается при небезопасных настройках и перечисляет проблемы с кодами. В demo и dev те же проблемы пишутся в лог предупреждениями.

| Признак | Причина | Что сделать |
|---|---|---|
| Запуск отклонён, код `cookie_insecure` | cookie сессии без флага Secure | задать `AISKRA_SESSION_COOKIE_SECURE=true` и входить по HTTPS; учебный контур без TLS — `AISKRA_PROD_ALLOW_HTTP=true` |
| Запуск отклонён, код `db_password` | пароль БД пустой или по умолчанию (`aiskra`, `postgres`, `password`, `changeme`, `secret`) | задать свой `POSTGRES_PASSWORD` в `.env` |
| Запуск отклонён, код `admin_password` | пароль администратора известный, содержит логин, короче 12 символов или меньше 3 видов символов | задать сильный `AISKRA_BOOTSTRAP_ADMIN_PASSWORD` |
| Запуск отклонён, код `external_ai` | в конфиге ИИ `allow_external: true`, а `AISKRA_AI_ALLOW_EXTERNAL=true` не задан | задать переменную или выключить `allow_external` |
| Ошибка конфигурации «внешний адрес … запрещён» | адрес модели вне локального контура при `allow_external: false` | указать локальный адрес модели или разрешить внешние адреса на демо-стенде |
| Ошибка подключения к БД после смены пароля | в пароле символы `@ : / ? #`, они ломают адрес БД | выбрать пароль без этих символов |
| Порт занят при `docker compose up` | 8080, 8443 или локальные 8000, 5432, 11434 заняты другой программой | освободить порт или изменить `ports` в `docker-compose.yml` |

Проверить настройки без запуска: `docker compose run --rm backend python -m aiskra.cli check-config`.

## Работа пользователей

| Признак | Причина | Что сделать |
|---|---|---|
| Браузер предупреждает о небезопасном соединении | самоподписанный сертификат nginx | принять сертификат в браузере или положить свой `server.crt` и `server.key` в том `tls`; имя сервера — в `TLS_SAN` |
| Кнопка голосового ввода недоступна: «Голосовой ввод работает по https или на localhost» | сайт открыт по HTTP; браузер не даёт микрофон | открыть по HTTPS (:8443) |
| «Голосовой ввод не настроен — вводите реплику текстом» | распознавание речи не подключено (`stt: fake`) | вводить реплики текстом или настроить `STT_*` |
| Реплики озвучиваются голосом браузера | серверный синтез не подключён (`tts: fake`) или вернул ошибку | штатно; для серверного голоса настроить `TTS_*`, резерв — `tts.fallback` |
| Собеседник отвечает шаблонно, плитка «ИИ-модели» жёлтая, «офлайн-режим» | модель не подключена или недоступна | проверить `config/ai.yaml` и адрес модели; «ИИ-модели» → пробный запрос; занятие продолжается без модели |
| Диспетчер ДДС получает 403 `dds_not_assigned`: «На занятии АРМ ДДС открыт только для вашей службы» | на идущем занятии диспетчер открыл чужую службу | выбрать службу, назначенную в занятии или группе |
| «Вход заблокирован» | 5 неверных паролей подряд | подождать 15 минут или задать новый пароль в разделе «Пользователи» |
| Пользователей выбросило из системы | восстановление из резервной копии завершает все сессии | войти заново |

## Обслуживание

| Признак | Причина | Что сделать |
|---|---|---|
| Плитка «Резервные копии» жёлтая | копий нет или последней больше 24 часов | создать копию; проверить ежедневную копию и час в настройках |
| Мало свободного места на плитке «Резервные копии» | копии и данные заполняют диск | уменьшить «Хранить копий», перенести скачанные копии, очистить аудит старше срока |
| Оповещение «Лог приложения: ошибок за 60 мин» | ошибки в работе сервера | открыть «Логи», фильтр «ошибки»; журнал контейнеров — `docker compose logs` |
| Плитка «База данных» красная, «БД недоступна» | нет подключения к PostgreSQL | `docker compose ps`, `docker compose logs db`; проверить `POSTGRES_PASSWORD` |
| Нет классификатора, служб или адресов | справочники не загружены, например после восстановления копии | импорт справочников в разделе «Состояние» |

## Стенд с Caddy и Let's Encrypt

| Признак | Причина | Что сделать |
|---|---|---|
| `stand status` показывает 200, снаружи сайт не открывается | проблема в сети: проброс портов, DNS | проверить запись A и проброс TCP 80 и 443; проверять с мобильного интернета, не из домашней сети |
| В `stand logs caddy` — `challenge failed`, `timeout` | Let's Encrypt не достучался до порта 80 | проверить запись A и проброс порта 80 |
| Сертификат не выдаётся около часа | несколько неудачных попыток: Let's Encrypt временно не выдаёт сертификат для имени | пока домен не готов, запускать `stand up --local` |
| OpenRouter отвечает 403 | ограничение доступа к API | прокси только для запросов ИИ: `AI_PROXY` в `stand.env`; VPN на весь трафик не включать |
