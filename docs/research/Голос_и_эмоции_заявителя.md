## 1. Задача
Команда просит добавить в АИскру голос из прототипа. Прототип — отдельный веб-агент на Node.js: оператор говорит «без рук», ИИ-звонящий отвечает эмоциональным голосом, и его состояние меняется от того, как с ним говорят.

Требования, которые это закрывает:

| Источник | Что требуется |
|---|---|
| [01](../brief/01_Консолидированные_требования.md) разд. 4.1 | вводная голосом (TTS) — «желательно» |
| 01 разд. 4.7 | диалог с заявителем чатом или голосом |
| 01 разд. 6.2 | голос участника и старшего группы через TTS, распознавание речи обучающегося |
| 01 разд. 8.7 | аудио в MP3/WAV |
| ответ заказчика #642 | проверяется соответствие сказанного голосом и заполненной карточки |
| 01 разд. 1.3, ответы #710, #746 | работа в изолированном контуре; внешний API — только на демо |
| профстандарт 12.002, A/01; [исследование подготовки](Подготовка_персонала_112_и_ЕДДС.md), строка 7 | работа с психологическим состоянием заявителя, «устойчивость к сложному заявителю» |

## 2. Что в прототипе
2 коммита, около 1 400 строк: `server.js` (Express, 234 строки) и `public/app.js` (895 строк, без фреймворка). Тестов нет, **файла лицензии нет**.

| Возможность | Как сделано | Параметры |
|---|---|---|
| Разговор «без рук» (VAD в браузере) | RMS-уровень с `AnalyserNode`; калибровка фона; адаптивный порог старта и остановки (гистерезис); старт — после N кадров голоса подряд; конец реплики — по устойчивой тишине | калибровка 900 мс, мин. речь 420 мс, тишина 680 мс, пауза между репликами 650 мс; профили «высокая / сбалансированная / строгая» — 3/4/5 кадров, множитель шума 2,1/2,4/2,8 |
| Перебивание (barge-in) | новая реплика оператора останавливает озвучку и обрывает поток ответа модели | — |
| Защита от эха | пока звучит агент, порог выше и нужно больше кадров; 900 мс после озвучки — повышенный порог; распознанный текст, на 65 % совпадающий по словам с последней фразой агента за 8 с, отбрасывается | `ECHO_GUARD_MS = 900`, `ECHO_MATCH_WINDOW_MS = 8000` |
| Состояние звонящего | 9 параметров: эмоция, интенсивность, темп, громкость, срочность, доверие, сотрудничество, дыхание, перебивания | начальное — по сценарию |
| Реакция на оператора | регулярные выражения по реплике: успокаивающие фразы снижают напряжение, обесценивающие повышают; чёткий вопрос повышает сотрудничество | шаг ±1…2, шкала 0–10 |
| Состояние от модели | модель начинает ответ строкой `TONE\|emotion=…\|intensity=…`, строка скрывается и перезаписывает состояние | — |
| Эмоциональная озвучка | OpenRouter `/audio/speech`, Gemini 3.8 Flash Lite TTS, голос Zephyr; директива эмоции **приписывается к тексту**: `(speak in Russian with fear emotion; …) текст` | PCM 24 кГц → WAV на сервере |
| Распознавание | OpenRouter `/audio/transcriptions`, JSON с base64 `input_audio` | `openai/whisper-1` |
| Ответ модели | потоковый (SSE), короткие реплики | `max_tokens` 120, температура 0,55, последние 10 реплик |

## 4. Что берём и что нет

| Идея прототипа | Решение | Почему |
|---|---|---|
| Динамическое состояние звонящего | **Берём с изменениями:** 4 хранимых параметра — эмоция, напряжение, доверие, готовность отвечать. Темп, громкость, дыхание и перебивания выводятся из них. Состояние хранится за звонком **на сервере** | Это ядро ценности для обучения: оператор учится успокаивать. Остальные 5 параметров прототипа — производные, хранить их — дублирование |
| Правила реакции на реплики оператора | **Берём с изменениями:** правила в домене, детерминированные, с защитой от накрутки | Работают без модели (офлайн-режим — основной в контуре заказчика), объяснимы преподавателю, тестируемы |
| Штраф за короткую реплику (`длина < 8`) | **Не берём** | «Адрес?» — нормальный вопрос оператора 112, краткость — норма опроса |
| Состояние от модели (`TONE\|…`) | **Откладываем (V5):** модель предлагает изменение, сервер ограничивает шаг | Бесплатные модели демо-стенда нестабильно держат формат. Реплика оператора идёт в модель — оператор мог бы «приказать» заявителю успокоиться |
| Эмоциональный синтез речи | **Берём:** адаптер `TTSPort` к OpenAI-совместимому `/audio/speech` | Порт уже есть; один адаптер покрывает OpenRouter и локальный Speaches |
| Директива эмоции внутри текста | **Не берём:** эмоция передаётся **параметрами провайдера** — `speech_metadata.style` (Google), `instructions` (OpenAI), для Piper — только темп | Модель без поддержки инструкций прочитает директиву вслух; OpenRouter документирует штатные параметры (раздел 9) |
| VAD, перебивание, защита от эха | **Берём:** переносим алгоритм и подобранные значения в хук React | Нулевая зависимость, параметры уже подобраны автором. Режим «без рук» — опция, кнопка «говорить» остаётся |
| Обрыв ответа модели при перебивании | **Не берём:** реплики оператора ставятся в очередь | Ответ собеседника сохраняется на сервере вместе с репликой — это данные для автооценки (3.4). Обрыв на клиенте оставил бы в звонке реплику, которую оператор «не услышал» |
| Распознавание base64 JSON | **Не нужно** | OpenRouter принимает и multipart ([документация](https://openrouter.ai/docs/guides/overview/multimodal/stt)) — наш адаптер уже совместим |
| Потоковый ответ (SSE) | **Откладываем (V5)** | Меняет контракт реплики и CQRS-обработчик; выигрыш — около 1 с на первой фразе |
| Системный промпт и «скрытые факты» в браузере | **Не берём** | Обучающийся видит легенду в DevTools — нарушение R3.3-02 |
| Открытый прокси `/api/chat` с моделью от клиента | **Не берём** | Любой клиент тратит ключ на любую модель и любой промпт |
| Сценарии 911 в коде | **Не берём** | У нас банк сценариев из классификатора (3.2, 4.1) |
| Воспроизведение через `blob:` URL | **Не берём:** `<audio src="/api/v1/…">` | CSP стенда (`default-src 'self'`, `infra/nginx/templates/default.conf.template`) не пускает `blob:` в медиа — на TLS-стенде звук молча не заиграет |

## 5. Замечания к коду прототипа
Эти недостатки нельзя переносить вместе с идеями.

1. **Утечка легенды.** Системный промпт со «скрытыми фактами» собирается в браузере и уходит с клиента.
2. **Открытый прокси.** `/api/chat` принимает от клиента модель и любые сообщения — ключ OpenRouter тратится на что угодно.
3. **Только внешний API.** Всё завязано на OpenRouter — противоречит 01 разд. 1.3 без адаптера на локальную модель.
4. **Состояние не сохраняется.** Оно живёт в переменной браузера: не видно преподавателю, не попадает в оценку, теряется при перезагрузке.
5. **Ошибки через `window.alert`.** Сбой синтеза обрывает разговор.
6. **Лицензия.** Её нет, значит по умолчанию «все права защищены». Переносим идеи и подобранные значения, код пишем заново на TS/Python. Согласие и упоминание автора (zhamilka1) — решение команды (спецификация 3.6, раздел 6).

**Вывод:**
- демо — OpenRouter Gemini TTS (стиль штатным параметром), запасной бесплатный вариант — Fish Audio после проверки;
- контур заказчика — Speaches с Piper: эмоция передаётся темпом и словами реплики, голосом — нет;
- без настроенного синтеза — браузер с темпом, высотой и громкостью по состоянию. Этот вариант работает всегда и сразу.

## 7. Задержка и ресурсы
**Задержка одного обмена репликами** (оценка):

| Звено | Время |
|---|---|
| Конец речи (VAD) | 0,7 с |
| Whisper на GPU | < 1 с |
| Whisper на CPU | 2–5 с |
| Ответ модели (демо, `nemotron`, без рассуждений) | около 2 с |
| Синтез Gemini | около 1 с |

Итого около 4–5 с до первого звука. Текст ответа показывается сразу, звук — вдогонку.

**Время карточки.** В голосовом режиме в норматив 75 с входит время речи собеседника — как на реальном вызове. Задержка модели — искусственная. Поэтому режим звонка фиксируется за звонком и показывается в отчёте (R3.6-22).

**Память.** `CachingTTS` сейчас кладёт аудио в base64 в общий кеш ответов моделей: `max_items: 20000`, при 50–150 КБ на фразу это до 1–3 ГБ. Для сервера из ТЗ и для 8 ГБ у разработчика это опасно. Кешу аудио нужен свой лимит **в мегабайтах** (R3.6-12).

**Сервер из ТЗ** (6 ядер, без GPU): Piper — десятки миллисекунд на фразу, Whisper small — секунды на реплику.

## 8. Риски
| Риск | Мера |
|---|---|
| Стоп-код 29.09 23:59, заморозка стенда в 22:00 | Этапы V1–V5; всё выключено по умолчанию (`tts.kind: fake`, «без рук» — по переключателю); V3 и дальше — после стоп-кода в новой ветке |
| Бесплатный лимит OpenRouter (50 запросов в сутки) делят реплики и синтез | Синтез — отдельный ключ `TTS_API_KEY`, по запросу, с кешем; без ключа — озвучка браузером |
| Оператор «накручивает» доверие дежурными фразами или успокаивает одной длинной репликой | Категория правил срабатывает раз на реплику, фраза — раз за звонок, суммарное успокоение ограничено: паникующего заявителя успокаивают за 3 реплики |
| Эхо динамиков в классе без гарнитур | `echoCancellation`, повышенный порог во время озвучки, отбрасывание эха по словам; режим «без рук» — опция |
| Изменение промпта заявителя меняет поведение на стенде | Промпт `v2` — новая версия, кеш по версии; офлайн-ответы меняются только окраской, факты те же |
