# Модуль «психологическое состояние заявителя» для тренажёра оператора 112 — технические источники

Дата сбора: 27.09.2026. Контур: изолированный сервер (6 ядер, 32 ГБ ОЗУ, без GPU), опционально RTX 4060 8 ГБ на демо-стенде; русский язык.

Условные обозначения:
- **[проверено]** — факт взят со страницы, открытой при подготовке (GitHub / HuggingFace / arXiv / официальная документация).
- **[не проверено]** — оценка или вывод составителя; перед использованием в документах нужна проверка.
- Лицензии указаны по состоянию на дату сбора. Для гос-/коммерческого внедрения их нужно перепроверить юристом: «NC» означает запрет коммерческого использования.

---

## 0. Кратко

1. **Текст.** Если LLM просто «играет роль по легенде», она работает плохо: персонаж слишком кооперативен, быстро «сдаётся» и успокаивается, эмоции получаются однообразными. Все работающие системы (PATIENT-Ψ, SimPatient, EmoPatient, Sim911, DispatchMAS, CARS/ResistClient) выносят состояние **за пределы LLM**: скрытые переменные с числовыми шкалами обновляются после каждой реплики тренируемого, а генератор реплик получает их на вход. Факты легенды хранятся отдельно («fact commons» / валидация с перегенерацией).
2. **Голос, CPU.** Эмоционального open-source TTS для русского, который работал бы быстро на CPU, **нет**. Реалистичный вариант: Silero v5 (очень быстрый, SSML rate/pitch/break, но лицензия CC BY-NC-SA) или Vosk-TTS (Apache-2.0) плюс DSP-постобработка (питч/темп/тремор/дыхание), вставки невербальных сэмплов (плач, всхлипы, одышка), фоновый шум сцены и эмуляция телефонного канала (8 кГц, 300–3400 Гц, μ-law / GSM).
3. **Голос, GPU 8 ГБ.** Настоящее управление эмоциями с русским языком и разрешающей лицензией: **Chatterbox Multilingual V3** (MIT, русский, параметр `exaggeration`), **Qwen3-TTS 0.6B/1.7B** (Apache-2.0, русский, эмоции через текстовую инструкцию), **Fun-CosyVoice3 0.5B** (Apache-2.0, русский, instruct), **ESpeech-TTS-1 RL-V2** (Apache-2.0, русский F5-TTS; эмоция передаётся через эмоциональный референс).
4. **Оценка оператора.** Самый надёжный слой — интерпретируемые метрики: темп по word-timestamps faster-whisper, паузы и перебивания по silero-vad (MIT), громкость и F0. Русские SER-модели (Aniemore, HuBERT на Dusha) годятся только как вспомогательный сигнал: модель Aniemore, обученная на «актёрском» RESD, на реальной речи Dusha даёт точность 0,10. openSMILE/eGeMAPS разрешён только для исследований и образования, для коммерческого продукта нужна платная лицензия.
5. **Этика.** Для суицидальных и травматических сценариев нужны опт-ин, пребрифинг, возможность остановить сценарий, дебрифинг с инструктором и обратная связь. В RCT без обратной связи эмпатия обучающихся **снижалась**. Кроме того, safety-выравнивание LLM приводит к выходу из роли в тяжёлых сценариях, и это нужно учитывать в архитектуре.

### 1.2 Выводы для архитектуры (синтез)

Все работы сходятся в одном: **состояние не должно жить только в «голове» LLM**. Рекомендуемая схема [не проверено; синтез по SimPatient, EmoPatient, Sim911, DispatchMAS, CARS]:

```
реплика оператора (текст Whisper + акустические метрики)
   │
   ▼
[1] Классификатор действий оператора (LLM-джсон или правила):
    {успокаивает, чёткий закрытый вопрос, открытый вопрос, повтор/уточнение адреса,
     инструкция по первой помощи, эмпатия/называние эмоции, перебивает, повышает голос,
     обвиняет/спорит, молчит >N с, жаргон, «ложный вызов — предупреждение об ответственности»}
   │
   ▼
[2] Детерминированный движок состояния (Python, не LLM):
    переменные 0..1: arousal (возбуждение), distress, anger, trust_to_operator,
    coherence (связность), compliance, disclosure_level (сколько фактов можно отдать),
    fatigue / consciousness (для ступора, опьянения, травмы)
    + дискретная «фаза» (state machine): ПАНИКА → ЧАСТИЧНЫЙ КОНТРОЛЬ → СОТРУДНИЧЕСТВО,
      с возможным откатом (ЭСКАЛАЦИЯ) и терминальными состояниями (БРОСИЛ ТРУБКУ, ПОТЕРЯ СОЗНАНИЯ)
    Переходы: таблица «действие оператора → Δпеременных» × профиль состояния,
    с инерцией (EMA), порогами и случайным шумом; сценарные триггеры по таймеру
    (ухудшение пострадавшего, огонь приближается).
   │
   ├──► [3] «Реестр фактов легенды» (адрес, число пострадавших, что случилось):
   │        выдаются только при disclosure_level ≥ порога; искажаются при coherence < порога
   │        (например, пьяный путает номер дома). Валидация реплики: нет выдуманных фактов.
   │
   ▼
[4] LLM-генератор реплики: получает карточку персонажа, фазу, числовые переменные,
    разрешённые факты, стилевые правила фазы (длина фраз, повторы, обрывы, мат-уровень),
    «сначала мотивация (скрыто) → потом реплика» (идея RIMR).
    Возвращает JSON: {text, nonverbal:[sob, gasp, …], intensity, speech_rate, hangup:bool}
   │
   ▼
[5] Валидатор (правила + принципы от инструктора, как в Roleplay-doh; до 2–3 перегенераций, как в Sim911)
   │
   ▼
[6] Голосовой рендер (раздел 2–3) — получает те же intensity/arousal
```

Важные эвристики [не проверено; следуют из CARS, RIMR, CLPsych 2026]:
- **Асимметрия**: эскалация быстрая (1 грубая реплика), деэскалация медленная (нужно 2–4 «правильных» действия подряд).
- **Откаты**: при резком триггере (грубость, долгая тишина, «повторите адрес» в пятый раз) состояние возвращается к исходной фазе.
- **Потолок кооперативности** задаётся профилем: у ложного вызова или агрессора compliance не растёт выше 0,4–0,6, как бы хорошо ни работал оператор.
- **Шум**: добавлять стохастику, чтобы одинаковые действия не давали идентичных реакций. Иначе обучающийся «выучит» бота.
- В лог писать **траекторию состояния** и связь каждого скачка с репликой оператора. Это материал для разбора (как дашборд SimPatient).

### 1.3 Как состояние влияет на текст (профили для генератора)

| Состояние | Текст (для LLM) | Голос (для TTS/DSP) |
|---|---|---|
| Паника | короткие фразы, повторы («скорее, скорее»), перескоки, не слышит вопросы, адрес по частям | быстро (rate fast/x-fast), высокий питч, прерывистое дыхание, повышенная громкость |
| Истерика | крик, обрывы, обвинения, неразборчивые куски, отказ отвечать | крик (клиппинг/компрессия), резкие перепады громкости, всхлипы |
| Плач | фразы прерываются, «...», слова тонут | медленнее, тремор питча (вибрато 5–8 Гц), вставки всхлипов и шмыганья |
| Агрессия | грубость, претензии («сколько можно ждать»), угрозы, мат по уровню | громко, низкий/средний питч, быстрый темп, жёсткая компрессия |
| Ступор / апатия | односложно, долгие паузы, «не знаю», не инициирует | медленно (x-slow), низкий питч, монотонно, паузы 2–5 с |
| Спутанность | противоречия, неверные ориентиры, путает время и место | обычный темп, запинки, паузы в середине фраз |
| Опьянение | повторы, растянутые слова, перескакивает, путает адрес | медленно, «смазанность» (time-stretch + лёгкий LPF), неровный темп |
| Ребёнок | простая лексика, не знает адреса, называет «мама», ориентиры «у магазина» | нужен детский голос: питч-шифт +3…+5 полутонов и форманты, либо voice design (Qwen3-TTS) |
| Пожилой | медленно, переспрашивает, не слышит, подробности не по делу | медленно, тремор, низкая громкость, «плохой слух» в диалоге |
| Суицидальный | амбивалентность, прощальные формулировки, не говорит о месте; **без описания способов** | тихо, медленно, плоская интонация |
| Ложный вызов / хулиган | противоречия, смех, провокации, резкие смены темы, «проверка» оператора | смех на фоне, голоса друзей, неестественные паузы |

### 2.2 Коммерческие российские (только справка, облако — в изолированном контуре неприменимы)

- **Yandex SpeechKit** — https://aistudio.yandex.ru/ru/docs/speechkit/tts/voices [проверено]: у голосов есть «амплуа». `evil` (раздражённая): jane, omazh. `whisper`: marina и др. `strict`: julia, kirill, masha и др. Также есть `good`, `friendly`, `neutral`. Детских голосов в списке нет.
- **SberDevices SaluteSpeech** — https://developers.sber.ru/docs/ru/salutespeech/guides/synthesis/ssml [проверено]: SSML `<paint>` (pitch, slope, speed, loudness), `<voice mode>` (управление эмоцией, только для русского), `<extra.background-audio>` (фоновый звук), `<break>`, `<say-as>`, ударения `'` и акценты `*`.

Их роли можно использовать как ориентир для набора «эмоциональных пресетов», но в офлайн-контур они не встраиваются.

### 2.3 Практические замечания [не проверено; оценка составителя]

- Эмоции у мультиязычных моделей (Chatterbox, CosyVoice, Qwen3) обучены в основном на китайском и английском. На русском возможны акцент, ошибки ударений и «переигрывание». Нужен A/B-прогон на 20–30 фразах каждого состояния. Для ударений использовать RUAccent или ручные `+`.
- Для клонирования нужны **собственные** референсные записи актёров с письменным согласием на каждое состояние («плачет», «кричит», «шепчет»). Голоса реальных звонивших в 112 использовать нельзя (персональные данные, этика).
- Для 8 ГБ VRAM: Qwen3-TTS 1.7B в bf16 — около 3,5 ГБ весов, должен поместиться вместе с кэшем. Chatterbox 0,5B и CosyVoice3 0,5B тоже помещаются. Но LLM на той же карте конкурирует за память, поэтому на демо-стенде LLM лучше держать на CPU/квантованной или в отдельном процессе.

### 3.3 Телефонный канал (цепочка) [не проверено: параметры по общеизвестным стандартам ITU-T G.711; страница ITU при проверке вернула 500]

```
TTS 24/48 кГц → эмоциональный DSP (pitch/tempo/tremolo/vibrato, gain envelope)
→ микс с невербаликой (по тегам LLM) → микс с фоном сцены (SNR 5–20 дБ, по фазе сценария)
→ ресемплинг 8 кГц → полосовой фильтр 300–3400 Гц → μ-law (G.711) кодирование/декодирование
   или GSMFullRateCompressor (мобильный) → опционально пакетные потери (выпадение 20–60 мс фреймов),
   «обрыв связи» (тишина/гудки), клиппинг при крике
```

- «Обрыв связи»: LLM выставляет флаг `hangup`, или сценарий обрывает звонок по таймеру. Воспроизводятся короткие гудки (синтез тона 425 Гц, каденция занято) — [не проверено: параметры тона для РФ проверить по нормативу].
- Silero умеет генерировать сразу в 8 кГц, но фильтрацию и кодек лучше делать отдельно, чтобы фон и невербалика проходили через тот же канал.

**Рекомендуемые метрики оператора** [не проверено; конструкция составителя]:

- Темп: слов в минуту по word-timestamps. Целевой коридор задаёт методист 112 (например, замедление при панике абонента).
- Перебивания: число и длительность наложений речи оператора на реплику заявителя. Разделять «вынужденные» (заявитель кричит бессвязно) и «преждевременные».
- Паузы: латентность ответа, эпизоды тишины длиннее N с, влияющие на эскалацию заявителя.
- Содержательная часть (задал ли вопросы по протоколу, назвал ли адрес повторно) — по тексту, через LLM или правила.
- Все метрики показывать **на таймлайне рядом с траекторией состояния заявителя**, например «на 01:12 вы повысили голос — arousal заявителя вырос с 0,6 до 0,85».

Стандартизированные пациенты эффективны. Сценарии рекомендуется строить с участием людей с lived experience. Дебрифинг 45–60 мин после каждой симуляции. В части программ во время занятий дежурят специалисты по кризисной помощи на случай острой стрессовой реакции. |

**Рекомендации к модулю** [не проверено; синтез]:
1. **Опт-ин и маркировка.** Сценарии «суицид», «гибель ребёнка», «насилие» — отдельная категория. Включаются инструктором, обучающийся заранее знает тему (без спойлера деталей) и может отказаться без последствий для оценки.
2. **Кнопка «пауза / выход из сценария»** у обучающегося и у инструктора. Мягкое завершение: заявитель «соглашается дождаться бригаду».
3. **Уровни интенсивности** (1–3) для тяжёлых состояний: плач, крик и натуралистичные звуки на уровне 1 приглушены.
4. **Контент-ограничения генератора**: никаких описаний способов суицида, натуралистичных описаний травм и крика боли ребёнка на максимальной громкости. Этот стоп-лист проверяет валидатор (п. [5] архитектуры).
5. **Защита от выхода из роли**: локальная модель с явным учебным фреймингом в системном промпте. Детектор фраз вида «как ИИ…» / «обратитесь на линию…» с перегенерацией. Резервные скриптовые реплики, написанные методистом, для ключевых моментов суицидального сценария.
6. **Обязательный дебрифинг** с инструктором после тяжёлых сценариев. Автоматический разбор (таймлайн метрик) — дополнение, а не замена.
7. **Данные**: не использовать записи и голоса реальных звонивших. Легенды обезличивать. Записи обучающихся хранить по правилам ПДн (152-ФЗ) с согласием. Эмоциональные метрики оператора не использовать для аттестационных санкций без валидации.
8. **Стереотипы**: профили «пьяный», «пожилой», «ребёнок», «иностранец» проверяет методист, чтобы не получилась карикатура. У LLM и TTS есть собственные смещения.

## 6. Рекомендованный стек

### 6.1 Базовый: офлайн, только CPU (6 ядер / 32 ГБ)

| Слой | Выбор | Почему |
|---|---|---|
| Движок состояния | собственный Python-модуль: state machine + непрерывные переменные + таблица переходов по действиям оператора + реестр фактов | детерминированность, объяснимость, лог траектории для разбора (SimPatient, CARS) |
| Классификатор действий оператора | та же LLM в режиме JSON (короткий промпт) + правила (ключевые слова, акустика: громкость/перебивание) | без дополнительных моделей |
| Реплики | существующая LLM проекта; промпт: карточка персонажа + фаза + переменные + разрешённые факты + стилевые правила; валидатор + до 2 перегенераций | Sim911, Roleplay-doh |
| TTS | **Silero v5_5_ru** + SSML `prosody rate/pitch`, `break` (если допустима лицензия CC BY-NC-SA для учебного некоммерческого стенда); иначе **Vosk-TTS (Apache-2.0)** | Silero ≈ 90–110 с аудио/с на 4 потоках: TTS почти не нагружает CPU, ресурсы остаются для LLM и Whisper |
| Эмоциональный DSP | audiomentations (MIT) / numpy+scipy: PitchShift, TimeStretch, тремоло/вибрато для плача, GainTransition, ClippingDistortion для крика; вставка дыхания и всхлипов между фразами по тегам LLM | эмоции «достраиваются» поверх нейтрального TTS |
| Невербалика и фон | собственный банк CC0/CC BY (Freesound, FSD50K-CC0/BY, MUSAN) + атрибуции; микс по фазе сценария | чистые лицензии |
| Канал | ресемплинг 8 кГц + BandPass 300–3400 Гц + μ-law (scipy/audioop-аналог или ffmpeg `pcm_mulaw`) ; опционально pedalboard `GSMFullRateCompressor` (GPL-3.0) | реализм, заодно маскирует артефакты TTS |
| STT оператора | faster-whisper (small/medium int8) + word_timestamps + vad_filter | темп и паузы |
| Паралингвистика | silero-vad (перебивания, паузы) + F0/RMS (librosa/numpy) ; openSMILE eGeMAPS — только в пилоте (NC) ; SER (HuBERT-Dusha) — вспомогательно | интерпретируемые метрики важнее классификатора эмоций |

Бюджет CPU [не проверено; оценка]: TTS < 0,5 ядра в среднем; silero-vad пренебрежимо мал; faster-whisper small int8 — 1–2 ядра; основная нагрузка — LLM. Для детского голоса на CPU: Silero `pitch="x-high"` + PitchShift с сохранением формант (оценочно выйдет «мультяшно») либо заранее сгенерированные на GPU фразы.

### 6.2 Улучшенный: демо-стенд с RTX 4060 8 ГБ

| Слой | Выбор |
|---|---|
| TTS основной | **Chatterbox Multilingual V3** (MIT, русский): `exaggeration` связывается с arousal заявителя (0,3 ступор … 0,9 истерика); отдельные референсы-голоса актёров на каждое базовое состояние |
| TTS альтернативы | **Qwen3-TTS 0.6B/1.7B** (Apache-2.0): эмоция задаётся текстовой инструкцией из движка состояния, VoiceDesign для ребёнка и пожилого. **Fun-CosyVoice3 0.5B** (Apache-2.0): instruct. **ESpeech-TTS-1 RL-V2** (Apache-2.0, русский F5): эмоция через референс, лучшее русское произношение среди F5-вариантов с разрешающей лицензией |
| Невербалика | как в CPU-варианте (сэмплы). Русскоязычных open-source TTS со встроенными надёжными тегами `[sob]` нет: Dia и Chatterbox-Turbo/Nano только английские, Fish (теги, русский) — некоммерческая лицензия |
| Канал и фон | тот же DSP-слой (общий код) |
| STT | faster-whisper large-v3 / turbo на GPU (int8/fp16) |
| Fallback | при нехватке VRAM или сбое — Silero/Vosk + DSP (тот же интерфейс `render(text, state) → wav`) |

**Интерфейс модуля** (чтобы TTS можно было менять) [предложение]:

```json
  "nonverbal": [{"type": "sob", "at": "before"}, {"type": "gasp", "at": "after:1"}],
  "voice_id": "female_35_actor2",
  "scene_bg": "apartment_fire", "channel": "mobile_gsm", "hangup": false
}
```
