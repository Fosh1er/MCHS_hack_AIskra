# Ранбук стенда финала (F6.7)

Как держать демо-стенд АИскры с 20.10 до питча 23.10. Что делать, если что-то сломалось перед экспертами.

## 1. Постоянный адрес
Быстрый туннель `trycloudflare.com` меняет адрес при каждом перезапуске — для финала не годится. Варианты по убыванию надёжности:
1. **VPS с доменом команды:** `docker compose` + свой сертификат в томе `tls` (`server.crt`, `server.key`). Адрес не зависит от домашней машины.
2. **Именованный туннель Cloudflare:**
   - на машине со стендом: `cloudflared tunnel login` → `cloudflared tunnel create aiskra`;
   - DNS-запись на домен команды: `cloudflared tunnel route dns aiskra aiskra.<домен>`;
   - конфиг `~/.cloudflared/config.yml`: `ingress: [{hostname: aiskra.<домен>, service: https://localhost:8443, originRequest: {noTLSVerify: true}}, {service: http_status:404}]`;
   - запуск службой: `sudo cloudflared service install`.

   Адрес сохраняется при перезапусках.

Машина со стендом не засыпает:
- macOS: `caffeinate -dimsu`;
- Linux: `systemctl mask sleep.target suspend.target hibernate.target hybrid-sleep.target`.

## 2. Запуск
```bash
git pull && docker compose up --build -d
docker compose exec -e AISKRA_DEMO_PASSWORD backend python -m aiskra.cli demo-seed
docker compose exec -e AISKRA_DEMO_PASSWORD backend python tools/demo_history.py
curl -sk https://localhost:8443/health
```

В `.env` стенда:
- `AISKRA_APP_ENV=demo` — вход одним кликом (F2);
- конфиг модели из F3 с лимитом расходов на ключе (`AISKRA_AI_CONFIG=ai.openrouter.yaml`, `AISKRA_AI_ALLOW_EXTERNAL=true`, `DEMO_LLM_API_KEY`);
- для голоса — `TTS_KIND=openai_compatible`, `STT_KIND=openai_compatible`.

`/health` должен показать `"env":"demo"` и версию.

## 3. Мониторинг
- Внешняя проверка `https://<адрес>/health` раз в минуту — любой бесплатный сервис uptime-мониторинга. Оповещение — в чат команды.
- Страница администратора «Состояние»: подсистемы и ошибки за час (п. 10.6).
- Ключ модели: остаток и расходы смотреть в кабинете провайдера утром и перед питчем.

## 4. Если что-то сломалось
| Симптом | Действие | Время |
|---|---|---|
| Заявитель отвечает «по правилам», хотя модель настроена | «ИИ-модели» → пробный запрос. Ключ или лимит → пополнить или сменить модель в `.env` (`DEMO_LLM_MODEL`), `docker compose up -d backend` | 2 мин |
| Модель медленная (первое слово > 3 с) | Переключить `applicant_actor` на быструю модель из отчёта F3 или временно на офлайн: `AISKRA_AI_CONFIG=ai.yaml` | 2 мин |
| Нет голоса | Выключить серверный синтез (`TTS_KIND=fake`) — озвучит браузер | 1 мин |
| `/health` не отвечает | `docker compose ps`, `docker compose logs --tail 100 backend`, `docker compose restart backend` | 2 мин |
| В логе backend «Запуск в режиме prod … отклонён» | В `.env` нет `AISKRA_APP_ENV=demo` (по умолчанию — prod) или пароли по умолчанию. Исправить по списку в сообщении (ADR-0015), `docker compose up -d backend` | 2 мин |
| Сломаны данные демо | `demo-seed` (учётки и сценарии не дублируются), при необходимости — восстановление из резервной копии в «Настройках и копиях» | 5 мин |
| Адрес не открывается снаружи | Проверить туннель: `cloudflared tunnel info aiskra`, перезапуск службы | 2 мин |

## 5. Запасной план на питче
- Ноутбук докладчика держит тот же стенд локально (`docker compose`) в режиме `demo` с офлайн-ИИ — показ без сети.
- Гифка демо на слайде 7 и скринкаст `docs/demo/АИскра_скринкаст.mp4` — если не работает ничего.
- Сценарий показа на 3 минуты — техспека, раздел 7.

## 6. Заморозка
После загрузки решения на финал стенд не обновляется: оценивают зафиксированное состояние. Нужен фикс — сначала согласовать с организаторами.
