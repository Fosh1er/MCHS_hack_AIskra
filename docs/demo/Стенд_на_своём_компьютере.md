# Стенд АИскры на своём компьютере под своим доменом

Сайт работает прямо на компьютере (macOS): backend, собранный фронтенд и [Caddy](https://caddyserver.com) — веб-сервер, который сам получает и продлевает сертификат Let's Encrypt. Docker и туннели не нужны. Домен смотрит на внешний IP дома, роутер пропускает порты 80 и 443 на компьютер.

Скрипт — `tools/stand/stand`. Настройки, база и журналы — вне репозитория, в `~/aiskra-stand` (папка задаётся `STAND_HOME`).

## Что нужно один раз

### 1. На компьютере
```bash
brew install caddy uv node
make be-install && make fe-install
```
Ключ OpenRouter — строка `DEMO_LLM_API_KEY=…` в `.env` репозитория: стенд читает его при запуске и в свои настройки не копирует. Нет ключа — стенд работает, заявитель отвечает по правилам, голоса модели нет.

### 2. У провайдера
Нужна услуга **«статический (белый) IP»**. Без неё внешний адрес меняется или делится между абонентами, и домен на него не направить. Проверка: адрес, который показывает [yandex.ru/internet](https://yandex.ru/internet), совпадает с адресом WAN в настройках роутера.

### 3. В роутере
- закрепить за компьютером постоянный адрес в домашней сети (резерв DHCP по MAC-адресу);
- пробросить порты **TCP 80 и 443** на этот адрес. Порт 80 нужен Let's Encrypt для проверки домена, 443 — для сайта.

### 4. В DNS домена (REG.RU: «Домены» → домен → «DNS-серверы и управление зоной»)
| Имя | Тип | Значение |
|---|---|---|
| `@` | A | внешний IP |
| `www` | A | внешний IP |

Если там уже есть записи A на заглушку REG.RU — заменить их. Записи AAAA для этих имён удалить. То же — для второго домена, если он указан в `STAND_ALIASES`. Записи расходятся за 15–60 минут; проверка: `dig +short mchs-training-mvp.ru @8.8.8.8`.

### 5. Настройки стенда
```bash
tools/stand/stand init
```
Создаёт `~/aiskra-stand/stand.env` (права 600: в нём пароли) и базу с демо-данными. В начале файла — домены:
- `STAND_DOMAIN` — основной адрес;
- `STAND_ALIASES` — остальные имена, они перенаправляются на основной;
- `ACME_EMAIL` — почта для писем Let's Encrypt, можно оставить пустой.

## Запуск
```bash
~/aiskra-stand/stand up
```
За 10–20 с собирается фронтенд, запускаются backend и Caddy. При первом запуске Caddy получает сертификат — до минуты. Сайт: `https://<STAND_DOMAIN>`. Пока стенд работает, компьютер не засыпает (`caffeinate`); крышку ноутбука без внешнего монитора не закрывать, питание — от сети.

| Команда | Что делает |
|---|---|
| `stand up` | собрать и запустить (повторный запуск перезапускает) |
| `stand up --local` | проверка без домена: `https://localhost` и адрес компьютера в домашней сети, сертификат локальный (браузер предупредит) |
| `stand down` | остановить |
| `stand status` | что запущено и отвечает ли сайт |
| `stand logs` / `stand logs caddy` | журнал backend / Caddy |

После перезагрузки компьютера — снова `stand up`.

В обоих режимах сайт открывается ещё и по адресу компьютера в домашней сети (`https://192.168.…`, сертификат локальный): дома можно проверить стенд, пока домен не заработал.

Не запускайте `stand up` под доменом, пока запись A не ведёт на этот компьютер: Caddy будет раз за разом пытаться получить сертификат, и после нескольких неудач Let's Encrypt временно (примерно на час) перестанет выдавать его для этого имени. Пока домен не готов — `stand up --local`.

## ИИ и VPN
- Если OpenRouter без VPN не отвечает (403), VPN нельзя включать «на весь трафик»: ответы посетителям сайта уйдут через VPN, и сайт снаружи перестанет открываться.
- Нужен режим, в котором через VPN ходят только запросы к ИИ. Большинство клиентов (Hiddify, Clash, v2rayN, Outline и др.) открывают на компьютере локальный прокси. Его адрес — в `AI_PROXY` в `stand.env`, например `AI_PROXY=http://127.0.0.1:7890`, затем `stand up`. Через прокси пойдёт только backend.
- Проверка: администратор → «ИИ-модели» → пробный запрос.

## Если не открывается снаружи
1. `stand status` — `сайт: … → 200` значит, на компьютере всё работает: проблема в сети.
2. `stand logs caddy` — ошибки получения сертификата (`challenge failed`, `timeout`) означают, что Let's Encrypt не достучался до порта 80: проверьте запись A и проброс портов.
3. Проверка снаружи — с телефона по мобильному интернету, не по домашней Wi-Fi: многие роутеры не открывают собственный внешний адрес изнутри сети.
4. macOS при первом запуске может спросить, разрешить ли входящие соединения для `caddy`, — разрешить.

## Безопасность
- Режим `demo`: на странице входа — вход в роли одной кнопкой, без пароля; администратор — только по паролю `AISKRA_BOOTSTRAP_ADMIN_PASSWORD` из `stand.env`.
- Кто знает адрес, тот пользуется ИИ за счёт ключа: на openrouter.ai поставьте на ключ лимит расходов.
- Заголовки безопасности сайта — те же, что у nginx в docker (`infra/nginx/templates/default.conf.template`); API отдаёт свои (`platform/security_headers.py`), cookie сессии — только по https.
