# Демо-стенд и скринкаст (п. 7.4)

## Скринкаст
[`АИскра_скринкаст.mp4`](АИскра_скринкаст.mp4) — 3 мин 31 с, 1600×900, 5 МБ. Путь из плана, с подписями шагов:

1. Преподаватель: банк сценариев, запуск смешанного занятия, мониторинг.
2. Оператор 112: входящий учебный вызов, опрос ИИ-заявителя, карточка (адрес из справочника, заявитель, тип по классификатору, опросная карта, пострадавшие, описание), службы на оранжевой панели, сохранение, автооценка.
3. Диспетчер ДДС «Служба 101»: карточка в очереди, «Принята» с номером наряда, звонок старшему группы по IP-телефону, статусы до «Работы завершены».
4. Преподаватель: мониторинг, отчёт с тепловой картой, разбор занятия, аналитика «норматив / факт», профиль обучающегося, допуск, достоверность автооценки.

Запись сделана автоматически (Playwright на Chrome) со стенда с демо-историей, ИИ — в офлайн-режиме. Перезаписать:

```bash
cd backend
AISKRA_DEMO_PASSWORD='…' uv run --with playwright --with httpx --with imageio-ffmpeg python tools/screencast.py --web http://localhost:5173 --out ../docs/demo
```

## Стенд: данные для показа
После запуска (docker compose или локально):

1. `make demo-seed` (в docker — `make demo-seed-docker`). Загружает справочники и адреса, 30 утверждённых сценариев, учётки `teacher`, `op1`, `op2`, `dds1`, `dds2` и группу «Смена 1 (демо)». Администратор создаётся из `AISKRA_BOOTSTRAP_ADMIN_PASSWORD`.
2. `make demo-history` (в docker — `make demo-history-docker`). Создаёт 6 прошедших занятий за 14 дней, около 100 оценённых карточек, у обучающихся разный уровень и кривая обучения. После этого аналитика, профили, допуск и прогресс на показе не пустые. Данные синтетические, в названии занятий стоит пометка «демо-история».

Демо-учётки обучающихся при первом входе показывают пошаговые подсказки по кнопкам (п. 5.3). На показе их можно продемонстрировать как возможность или закрыть «пропустить обучение»; скрипт скринкаста отключает их сам.

Оба шага берут пароль демо-учёток из `AISKRA_DEMO_PASSWORD`. Повторный `demo-seed` пароли существующих учёток не меняет: сменить пароль можно под `admin` → «Пользователи» → «Новый пароль».

## Режимы окружения (ADR-0015)
Режим задаёт `AISKRA_APP_ENV`. В docker compose по умолчанию — `prod`, у локального запуска без переменной — `dev`.

| | `prod` — контур заказчика | `demo` — публичный стенд | `dev` — разработка |
|---|---|---|---|
| Демо-вход (F2) | нет: эндпоинты отвечают 404, страница входа — как в АРМ-112 | лента «Демонстрационный стенд · данные синтетические», карточки ролей с кнопкой «Войти» | как `demo` |
| Swagger `/docs`, схема `/openapi.json` | только вошедшему администратору: без входа — 401, другой роли — 403 | открыты | открыты |
| Страница «ИИ-модели» | `/admin/ai`, только администратор (раньше `/dev/ai`; маршрутов `/dev` больше нет ни в одном режиме) | так же | так же |
| Логи | не подробнее INFO | как `AISKRA_LOG_LEVEL` | как `AISKRA_LOG_LEVEL` |
| Небезопасные настройки | **запуск отклоняется** с перечнем проблем | предупреждения в лог | предупреждения в лог |

**Когда prod не запустится.** Backend при старте сначала выполняет `python -m aiskra.cli check-config` (до миграций). В prod он останавливается, если:

| Проблема | Что задать в `.env` |
|---|---|
| `cookie_insecure` — cookie сессии без `Secure` | `AISKRA_SESSION_COOKIE_SECURE=true` (в docker compose уже так). Учебный контур без TLS в закрытой сети: `AISKRA_PROD_ALLOW_HTTP=true` — единственное переопределение, при каждом запуске пишется предупреждение |
| `db_password` — пароль БД пустой или по умолчанию (`aiskra`, `postgres`, …) | свой `POSTGRES_PASSWORD` |
| `admin_password` — `AISKRA_BOOTSTRAP_ADMIN_PASSWORD` слабый: известный, совпадает с паролем демо-учёток, содержит логин, короче 12 символов или меньше 3 видов символов из 4 | сильный пароль |
| `external_ai` — в конфиге ИИ `allow_external: true` без явного разрешения | `AISKRA_AI_ALLOW_EXTERNAL=true` или выключить внешние модели |

Сообщение выглядит так (`docker compose logs backend`):

```
Ошибка: Запуск в режиме prod (AISKRA_APP_ENV=prod) отклонён — небезопасные настройки:
  • [db_password] пароль БД пустой или по умолчанию — задайте свой POSTGRES_PASSWORD в .env …
Исправьте .env и перезапустите. Для демонстрационного стенда — AISKRA_APP_ENV=demo (ADR-0015).
```

Проверить настройки до запуска: `docker compose run --rm backend python -m aiskra.cli check-config`. Модель `fake` (офлайн-режим) в prod не ошибка: тренажёр работает по легенде и шаблонам, в лог пишется «модели не подключены».

**`/health`** — `env` (режим), `version` (sha коммита: `make up` передаёт его в сборку образа как `AISKRA_VERSION`; без него — `unknown`), `started_at` (время старта, UTC). По `version` и `started_at` видно, что выкладка прошла и процесс не перезапускался.

## Вход для экспертов: режим `demo` (F2)

В режиме `demo` эксперт входит в роль одной кнопкой, пароль ему не нужен и в README его нет. Кнопки есть у учёток `demo-seed` (`teacher`, `op1`, `op2`, `dds1`, `dds2`), которые есть в базе и не заблокированы. Администратор так не входит. Каждый такой вход пишется в аудит событием «Вход на демо-стенде без пароля» (`auth.demo_login`). С одного адреса — не больше 10 демо-входов в минуту.

Пароль демо-учёток показывается на странице входа у каждой роли (рекомендации экспертов финала); скрыть — `AISKRA_DEMO_SHOW_PASSWORD=false`. В `prod` — тоже, если задан `AISKRA_DEMO_PASSWORD` (выключить — `AISKRA_DEMO_IN_PROD=false`).

## Стенд по ссылке
Нужен сервер с Docker: ТЗ требует 6 ядер, 32 ГБ, без GPU; для демо хватит и 2 ядер с 4 ГБ, если модель внешняя.

```bash
git clone https://github.com/Fosh1er/MCHS_hack_AIskra.git && cd MCHS_hack_AIskra
cp .env.example .env
```

В `.env` задайте:

| Переменная | Значение |
|---|---|
| `AISKRA_APP_ENV` | `demo` — вход в роль одной кнопкой на странице входа |
| `POSTGRES_PASSWORD` | пароль БД (не `aiskra`; без символов `@ : / ? #`) |
| `AISKRA_BOOTSTRAP_ADMIN_PASSWORD` | пароль администратора (от 12 символов, 3 вида символов из 4) |
| `AISKRA_DEMO_PASSWORD` | пароль демо-учёток |
| `TLS_SAN` | имя или адрес сервера для сертификата, например `DNS:aiskra.example.ru,IP:1.2.3.4` |
| `AISKRA_AI_CONFIG` | `ai.openrouter.yaml` — демо на бесплатных моделях OpenRouter |
| `AISKRA_AI_ALLOW_EXTERNAL` | `true` |
| `DEMO_LLM_API_KEY` | ключ модели (только в `.env`) |

Затем:

```bash
make up        # docker compose up --build -d с версией (sha коммита) в /health
make demo-seed-docker && make demo-history-docker
```

Стенд открывается по адресу `https://<сервер>:8443`; режим проверяется запросом `https://<сервер>:8443/health` — поле `env` должно быть `demo`, `version` — sha выложенного коммита. Сертификат самоподписанный; свой сертификат кладётся в том `tls` как `server.crt` и `server.key`. Флаг внешней модели виден администратору на странице «ИИ-модели» (`/admin/ai`): провайдер, модель, пробный запрос.
