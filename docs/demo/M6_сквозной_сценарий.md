# Сквозной сценарий (M6): от вызова 112 до отчёта преподавателя

Сценарий для стенда, демонстрации и скринкаста. Проверен вручную 26.09.2026 в браузере под тремя ролями; тот же путь автоматически — `backend/tests/integration/test_e2e.py`.

## 1. Подготовка стенда (≈5 с на чистой базе)
```bash
export AISKRA_DEMO_PASSWORD='<пароль демо-учёток, от 8 символов>'
make demo-seed                          # локально; в docker — make demo-seed-docker
make demo-seed MATERIALS=/путь/к/материалам   # плюс учебные материалы (DOCX, PDF, XLSX, TXT)
```
Команда идемпотентна: справочники и адреса загружаются, если их нет; банк добирается до 30 утверждённых сценариев; создаются учётки и группа. Администратор — из `AISKRA_BOOTSTRAP_ADMIN_PASSWORD` (`ensure-admin` при старте контейнера).

| Логин | Роль | В группе «Смена 1 (демо)» |
|---|---|---|
| `teacher` | преподаватель | — |
| `op1`, `op2` | обучающиеся | операторы 112 |
| `dds1` | обучающийся | диспетчер ДДС «Служба 101» (пожарная) |
| `dds2` | обучающийся | диспетчер ДДС «Служба 103» (скорая) |

Для показа удобно три окна браузера (разные профили или окно инкогнито): преподаватель, оператор, диспетчер.

## 2. Шаги
| # | Кто | Действие | Что видно |
|---|---|---|---|
| 1 | `teacher` | Занятия → «новое занятие» → «Назначить группу: Смена 1 (демо)» → тип «Смешанное», карточки для ДДС «от операторов 112 занятия», категория «1. Пожары» → создать → «начать занятие» | Мониторинг: четыре плитки, часы занятия |
| 2 | `op1` | Вход → журнал 112 | Баннер занятия с часами и ролью; «поток вызовов» включён сам |
| 3 | `op1` | Входящий звонок (≈25–55 с) → «Ответить» | Открывается карточка 112, в панели — первая фраза ИИ-заявителя |
| 4 | `op1` | Вопросы в панели звонка: «Что случилось?», «Назовите адрес», «Есть пострадавшие?» | Заявитель отвечает по легенде, не выдавая лишнего |
| 5 | `op1` | Заполнить карточку (адрес из подсказки, тип, опросная карта, пострадавшие) → службы подбираются сами → «сохранить» | Панель автооценки с баллом и замечаниями |
| 6 | `teacher` | Мониторинг | У оператора — «карточек 1» и балл; у диспетчеров — карточка в очереди и таймер против норматива 30 с |
| 7 | `dds1` | Кабинет → «войти в занятие» → АРМ «Служба 101» | Карточка оператора первой строкой, «ждут решения» |
| 8 | `dds1` | Открыть карточку → «изменить статус»: «Принята» + номер наряда → «Начало реагирования» → «Прибытие» → «Работы начаты» → «Работы завершены», к каждому — комментарий | История статусов на вкладке службы |
| 9 | `dds1` | IP-телефон → «Старший группы» → «Доложите обстановку» | Старший группы отвечает по текущему статусу |
| 10 | `teacher` | Мониторинг → «завершить» → «отчёт» → «оценить все карточки» | Оценены оператор и диспетчер; карточка неоткрытой ДДС пропущена с объяснением |
| 11 | `teacher` | «раскрыть все» → «правка» у карточки → балл и комментарий | Балл, «зачтено» и сводка пересчитаны; правка — в аудите |
| 12 | `teacher` | Тепловая карта, время заполнения, динамика; «Excel (CSV)», «PDF» | Диаграммы по тем же числам, что в таблице |
| 13 | `op1`, `dds1` | Кабинет → история → «мои результаты» | Свои карточки, ошибки, комментарий преподавателя, рекомендации |

## 3. Что проверено при прогоне и исправлено
- В АРМ ДДС на узком экране IP-телефон закрывал редактор статуса. Теперь, пока открыт редактор, панель телефона сворачивается до заголовка.
- Мониторинг после повторного открытия страницы несколько секунд показывал старые цифры из кеша. Теперь он запрашивает свежие данные сразу.
- ИИ-заявитель говорил «2 человек(а)» и «Дорогомилово район». Теперь он склоняет слово «человек» и говорит «район Дорогомилово».
- Баннер занятия в АРМ ДДС показывал код службы «S101». Теперь он показывает её название.

## 4. Ограничения стенда
- Docker на машине разработки недоступен: прогон сделан локально (uvicorn + Vite, SQLite). `docker compose` проверяется на целевом сервере (M7).
- ИИ в офлайн-режиме: ответы заявителя и старшего группы детерминированы по легенде. С подключённой моделью (`config/ai.yaml`) речь живее, путь тот же.
