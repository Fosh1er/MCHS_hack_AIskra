## Этап 1. Эмулятор АРМ-112: роль «Оператор 112» (дни 2–5)

### 1.1. Карточка происшествия 112 (визуально 100% как оригинал) — P0
- **Фронт работ:** компоновка по 5 зонам (шапка с телефонами и таймером; заявитель и пострадавшие; адрес + описание; типы + опросные карты; оранжевая панель служб). Поля и поведение: АОН авто, «АОН»-копирование, флаг «зарубежный», канал связи, ФИО/статус заявителя (6 значений), пострадавшие Нет/Есть + количество, кнопки «нет контакта»/«срыв звонка» с модалом, поиск типа с синонимами, плашки частых типов, значимые типы, чипы выбранных типов, опросные карты по типу (зависимые вопросы), единая адресная строка с подсказками + авто-заполнение округа/района/улицы/дома, ручные квартира/подъезд/этаж/код/описательный адрес, описание со счётчиком N/1999 и предупреждением о 100 символах для 03, панель служб (авто + модал «Добавьте службы», основная — двойное подчёркивание), «сохранить» → модал «Список оповещаемых служб», таймер. Горячие клавиши Alt+… (минимум Alt+T/A/O/P/Q/Z/S, Insert, Esc).
- **Документация:** 03 разд. 1, 2, 6; 04 (описание карточки 112 по скриншотам).
- **Материалы:** `img/instr/image18.png`, `image37.png`, `image46.png` (полные карточки), `image16–17.png` (что случилось), `image19–22.png`, `image29.png` (адрес), `image34–35.png` (опросные карты 101/104), `image38–39.png` (описание), `image44.png` (пострадавшие, заявитель), `image47–50.png` (службы), `image56.png` (модал сохранения), `image11–12.png` (нет контакта); `img/card112/`, `img/card112_v2/` (карточка 112 от заказчика, включая оранжевую панель добавления служб); ответ #680.

- **Фронт работ:** функция `resolve_services(type, answers, address)`: главная служба + матрица классификатора по признакам (НД, УЛ, ПП, пострадавшие, правонарушение, газификация, перекрытие движения и т.д.) + территориальные ДДС по округу/району (префектура, управа, ЖКХ) + подчинённость объекта (школа → Департамент образования). Ручное добавление через модал.

## Этап 2. Эмулятор АРМ ДДС: роль «Диспетчер ДДС» (дни 3–6)

### 2.1. Реестр карточек службы и очередь — P0
- **Фронт работ:** список входящих карточек своей ДДС с одновременным поступлением (поток), таймеры по каждой ожидающей и по текущей, звуковое/визуальное уведомление о новой карточке, статусы «Новая / Принята / Отклонена / … / Работы завершены», цветовая кодировка как в АРМ ДДС.
- **Документация:** 01 разд. 5.1–5.2, 3.10; 04 (реестр ДДС).
- **Материалы:** `img/dds/` (СКРИНШОТ ДДСГСИ.docx — эталон внешнего вида реестра и карточки ДДС), `img/chat/photo_676_0.jpg`, `photo_692_0.jpg` (карточка ДДС, вопрос о службах); ответы #679–680, #709.

### 2.2. Карточка ДДС и действия — P0
- **Фронт работ:** просмотр карточки, пришедшей от 112 (read-only содержимое); кнопки «Принять» / «Отклонить» (с обязательным комментарием); блок «в какие службы ещё направлена карточка» с телефонами и кнопкой звонка; выбор бригад/сил своей службы (справочник); нижние поля статусов: «Принята» → «Начало реагирования» → «Прибытие» → «Проведение работ» → «Работы завершены», каждый с комментарием и временем; звонок заявителю по номеру из карточки. Службы не добавляются. Универсальный алгоритм для всех служб.
- **Документация:** 01 разд. 5.3–5.9; 06 разд. 2.3.
- **Материалы:** `img/dds/` (карточка ДДС, нижние поля статусов), `img/services/`; ответы заказчика #684, #691, #701, #739, #740.

### 2.3. Симулятор IP-телефона ДДС — P0 (имитация) / P2 (реальный SIP)
- **Фронт работ:** софтфон в интерфейсе, стилизованный под РТУ Т16Р (экран, DSS-клавиши служб/бригад, линии): исходящий звонок старшему группы → ИИ-«старший группы» отвечает текстом/голосом (доклад о выезде, прибытии, ходе работ); входящий звонок-доклад от бригады; звонок заявителю; журнал звонков; фиксация факта и времени звонка для оценки. Опционально: WebRTC/SIP через локальный SIP-сервер (Asterisk/FreeSWITCH) для реального аппарата.
- **Документация:** 01 разд. 6; 06 разд. 2.3.
- **Материалы:** `РТУ Т16Р_Datasheet_2024_ГСИ.pdf` (4.3" экран, 2×3.5" DSS-экраны, 42 клавиши, 20 SIP-линий, кодеки G.711/G.722/Opus); `img/instr/image71–75.png` (управление звонком в АРМ-112), `image77.png` (телефон Avaya); ответы #576, #638, #684, #691.

### 2.4. Смешанный режим: карточки от обучающихся-операторов 112 — P1
- **Фронт работ:** карточка, сохранённая обучающимся в роли 112, маршрутизируется в очереди ДДС других обучающихся согласно набору служб; преподаватель выбирает источник карточек (система / обучающиеся / смешанный).
- **Документация:** 01 разд. 3.9.
- **Материалы:** ТЗ «Сценарий: действия с карточками».

## Этап 3. ИИ-модуль (дни 2–7, параллельно)

### 3.1. Провайдер моделей — P0
- **Фронт работ:** интерфейс `LLMProvider` (OpenAI-совместимый API: внешний сервис / Ollama / vLLM локально), `STTProvider` (Whisper локально / внешний), `TTSProvider` (Silero/Piper локально / внешний); конфиг: URL, ключ, имя модели, таймауты; режим без GPU; демо на внешнем API + инструкция локального развёртывания компактной модели.
- **Документация:** 01 разд. 7.4, 7.7; сопроводительная документация → «Методы обработки данных», «Инструкция по установке».
- **Материалы:** ответы #710, #746, #748; ТЗ «Минимальные требования к серверу».

### 3.2. Генерация сценариев и эталонов — P0
- **Фронт работ:** выбор строки классификатора по категориям и сложности → LLM генерирует легенду заявителя (ФИО, статус, телефоны, адрес из справочника, объект, описание своими словами, пострадавшие, доп. признаки, «шум»: паника, неточности, лишние детали по уровню сложности) + эталонную карточку (тип, признаки, ответы опросной карты, службы через `resolve_services`, ключевые фразы описания) + эталонные действия ДДС (принять/отклонить, статусы, ожидаемые звонки) + эталонные регламентные фразы («Сообщение принято, дежурная бригада направлена на место»). Structured output (JSON schema). Пакетная генерация для банка сценариев; загрузка учебных билетов из датасета как seed.
- **Документация:** 01 разд. 3.2, 7.1; 03 разд. 4 (JSON-эталон); 05.
- **Материалы:** классификатор (col6–col14), опросные карты 101/103/104 (`img/instr/image34–35.png`, `image18.png`), инструкция разд. «Описание со слов заявителя» (лимит 100 символов для 03), билеты из датасета платформы (#652).

### 3.3. Ролевые агенты диалога — P0 (заявитель текстом) / P1 (голос, старший группы)
- **Фронт работ:** агент «Заявитель» (держит легенду, отвечает на вопросы оператора, не выдаёт лишнего, эмоциональный фон по сложности); агент «Старший группы реагирования» (доклады о выезде/прибытии/работах по таймлайну сценария); агент «Диспетчер смежной службы» (для звонков в другие службы). Ограничение: не раскрывать эталон.
- **Документация:** 01 разд. 4.7, 5.6, 6.2.
- **Материалы:** ответы #642, #691, #740 («Вы звонили в 112 по поводу… Что у вас случилось»).

### 3.4. Автооценка — P0
- **Фронт работ:** детерминированная часть: сравнение полей карточки с эталоном (тип — точное/группа, признаки, службы — precision/recall, адрес — нормализованное совпадение, статус заявителя, пострадавшие), тайминг (норматив 30 с по умолчанию, отклонение), порядок и полнота статусов ДДС, факт звонков, штрафы за срыв/пропуск; LLM-часть: смысловое соответствие описания легенде, полнота ключевых фактов, регламентность формулировок комментариев, грамматика и орфография (с подсветкой); итоговый балл по настраиваемым весам и порогам; объяснение ошибок обучающемуся; инсайты по группе.
- **Документация:** 01 разд. 4.5, 5.10, 7.2–7.3, 7.6; сопроводительная документация → «Методы обработки данных» (формулы, веса, метрики).
- **Материалы:** ТЗ сценарии 2–3 (отчёт: действия, ошибки, время, отклонение от норматива, грамматика), ТЗ «Критерии» (достоверность, проверка расчётов), ответ #642.

### 3.5. Валидация качества ИИ — P1
- **Фронт работ:** тест-набор из 30–50 сценариев с ручными эталонами; метрики: точность классификации типа/служб генератором, согласованность автооценки с экспертной (преподаватель ставит оценку → сравнение); отчёт «достоверность» для презентации.
- **Документация:** 01 разд. 7.6, 12.
- **Материалы:** ТЗ «Критерии экспертизы».

## Этап 4. Контур преподавателя (дни 4–8)

### 4.1. Управление сценариями — P0
- **Фронт работ:** список сценариев (фильтры: категория, сложность, статус утверждения, источник); карточка сценария: легенда, эталон, предпросмотр вопросов/ответов с подсветкой правильных; «Сгенерировать» (категории, количество, сложность); утверждение полное/частичное; редактирование; поле комментария для перегенерации; удаление.
- **Документация:** 01 разд. 3.1–3.7, 2.4.
- **Материалы:** ТЗ «Сценарий: Настройка учебной среды».

### 4.2. Занятие (сессия) — P0
- **Фронт работ:** создание занятия: тип (карточки 112 / действия с карточками ДДС / смешанный), категории, источник карточек, группа/обучающиеся, тайминг (30 с по умолчанию), пороги, темп очереди; старт/стоп; экран мониторинга в реальном времени (кто на какой карточке, таймеры, ошибки, очередь); завершение в любой момент.
- **Документация:** 01 разд. 3.8–3.12; 06 разд. 2.3 (#709 поток).
