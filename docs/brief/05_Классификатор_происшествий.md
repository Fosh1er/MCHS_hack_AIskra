# Классификатор происшествий (Классификатор_происшествий_v_046_11_ДТУ_15_11_2024.xlsx)

Источник: файл заказчика, передан в чат 17.09 (#483). Один лист, 90 колонок, ~1300 строк-типов происшествий.

## Как читать
- **col1–col4 (Г, п1, п2, п3)** — иерархический код: группа → признак 1 → признак 2 → признак 3. **col5 «Номер»** — семизначный код типа (например 1010101). Строки, у которых заполнена только группа (col5 короткий, 1–24), — заголовки групп.
- **col6** — группа происшествий для статистики службы 112.
- **col7–col9 «112-Признак.1/2/3»** — то, как происшествие выглядит для оператора 112: три уровня уточнения (например «на улице» → «мусор» → «открытое пламя»). Это и есть дерево опросной карты в блоке «Тип происшествия» карточки. Значение «Не отображается оператору 112» (144 строки) — тип задаётся не оператором, а другой службой.
- **col10** — дополнительные признаки, не влияющие на тип (чекбоксы в опросной карте: «Пострадавшие», «Нет доступа», «Применяется оружие», «Опасный груз» и т.п.).
- **col11 «Итоговый тип происшествия»** — итоговый текст типа в карточке 112. **col12** — тип по ЕКП (единый классификатор происшествий, 35 типов) или «Нет в ЕКП».
- **col13 «Сценарий реагирования»** — код вида `группа_номер` (например 1_2, 15_10). По ответу заказчика (#683): технические номера разработчиков 112, под каждый сценарий закладывается своя опросная карта оператора 112; под сценарий подтягиваются определённые ДДС. «без сценария» — 9 строк.
- **col14 «Главная служба»** — код главной реагирующей службы (MCHS, Police, AMBULANCE, MOSGAZ, MOSLIFT, AUTOROADS, MOSVODOCANAL, METRO, OEK, MOSGORTRANS, MOESK, MOEK, MZD, MGTS, MOSVODOSTOK, MOSCOLLECTOR, GORMOST, GKH, Dep.tszn, ZODD, MSPPN, DepEco, ZEMP).
- **col15–col90** — матрица «какая служба получает карточку и как она у неё называется». Значение в ячейке — либо название типа в классификаторе этой службы (например «пожар: мусор» у МЧС), либо «карточка-112» (служба получает карточку без своего типа), либо «нет реагирования», либо пусто (не получает). Часть служб имеет подколонки по признакам: МЧС — «Нет доступа»; ОДС ПСЦ — «Угроза людям», «Пострадавшие/погибшие», «Нет доступа»; МВД — «Правонарушение», «Пострадавшие»; СМП — «Пострадавшие», «Пострадавшие не на месте»; МОСГАЗ — «газификация»; ЦЭМП — угроза людям / пострадавшие / мед. помощь / эвакуация; ФСБ — «>5 чел / ОД»; Мосгортранс — «постр/погибшие», «перекрытие движения»; ГОРМОСТ — тоннель / пеш / ав; Департамент строительства — «стройка»; Департамент культуры — «объект из перечня».

## Как использовать в проекте
1. **Справочник типов происшествий** (дерево признаков 1→2→3 + доп. признаки + итоговый тип + ЕКП + главная служба) — импорт в БД тренажёра, опросная карта в карточке 112 строится по нему.
2. **Правило подключения служб**: по коду типа + выбранным доп. признакам вычисляется набор служб (колонки col15–col90 с непустыми значениями). Это автоподбор служб в карточке 112 и маршрутизация карточки в очереди ДДС. Территориальные службы (управа, округ, ведомство-владелец объекта) подтягиваются дополнительно по району и подчинённости объекта (#690) — нужен справочник районов/округов Москвы и типов объектов.
3. **Генерация сценариев ИИ**: LLM получает случайный тип из классификатора (с учётом выбранных преподавателем групп) и генерирует легенду заявителя; эталон карточки — тип, признаки, службы из классификатора.
4. **Оценка**: сравнение выбранного обучающимся типа/признаков/служб с эталонной строкой классификатора (точное совпадение типа, совпадение группы, полнота набора служб).
