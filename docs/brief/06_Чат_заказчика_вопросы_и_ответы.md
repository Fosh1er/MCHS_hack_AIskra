## 4. Противоречия и открытые вопросы

### Противоречия (как трактуем)
1. **Звонок заявителя.** ТЗ: «система имитирует звонок участника событий». #570: звонок исключаем, генерируем карточку 112 → ДДС. #624/#642: оператор 112 всё же получает вводную (текст от ИИ или голос) и заполняет карточку, оценивается соответствие. **Трактовка:** вводная для роли 112 — обязательна в текстовом виде, голос (TTS) — желательно; звонки ДДС↔службы — имитация в системе, реальная SIP-телефония — бонус.
2. **Валидация карточки в ДДС.** #638 (модератор): ДДС проверяет корректность. #739 (заказчик, позже): ДДС правильность не контролирует, только статусы и комментарии. **Трактовка:** приоритет у #739. Проверку карточки оцениваем у роли оператора 112.
3. **Локальный контур vs внешний API.** ТЗ: изолированный контур. #746: локальное развёртывание модели должно быть возможно, на демо допустим внешний API, эндпоинт модели — настраиваемый. **Трактовка:** абстракция провайдера LLM/STT/TTS с конфигом, демо на внешнем API, инструкция по локальному развёртыванию.
4. **Статусы.** Смена статусов — вручную диспетчером ДДС по информации от старшего группы (#691, #739).

## 5. Сводка требований из чата (для разработки)
- Один веб-интерфейс, одна учётка обучающегося, две учебные роли: **оператор 112** и **диспетчер ДДС**.
- **Оператор 112:** получает вводную от «заявителя» (ИИ-текст, желательно TTS-голос), заполняет карточку (адрес, заявитель, описание со слов, тип происшествия по классификатору с опросной картой), система подтягивает службы по опросной карте, возможно ручное добавление. Оценивается соответствие карточки и набора служб вводной.
- **Диспетчер ДДС:** карточки приходят потоком (одновременно), тайминг идёт по текущей и по ожидающим; принимает/отклоняет с комментарием; содержимое не валидирует; вручную выбирает бригады; звонит старшему группы через симулятор IP-телефона; проставляет статусы «Принята → Начало реагирования → Прибытие → Проведение работ → Работы завершены» с комментариями; может позвонить заявителю; службы не добавляет, видит кому ещё ушла карточка. Алгоритм универсален для всех служб.
- Службы к происшествию подтягиваются по району обслуживания и подчинённости объекта.
- Карточка и реестр обращений — визуально максимально близко к скриншотам АРМ.
- ИИ: настраиваемый эндпоинт модели, возможность локального развёртывания; на демо допустим внешний API.
