# Интерфейс АРМ-112 и АРМ ДДС по скриншотам заказчика

Источники: «СКРИНШОТ ДДСГСИ.docx» (`data/source/screenshots/dds/`, 20 кадров, учебный стенд 10.0.99.36, 17.09.2026), «СКРИНШОТ КАРТОЧКИ 112ГСИ.docx» (`data/source/screenshots/card112/`, 9 кадров), «КАРТОЧКА 112.docx» (`data/source/screenshots/card112_v2/`, 39 кадров), «СЛУЖБЫ 112.docx» (`data/source/screenshots/services/`, 55 кадров прокрутки справочника служб). Все кадры 1920×1080, браузер Яндекс, масштаб 80–90%.

Требование заказчика (#679, #680): повторить цвета и конфигурацию; **карточка и реестр обращений должны быть похожи на 100%**, второстепенные экраны — свободно.

Подписи заказчика в документах:
- ДДС: «Вход в систему для ДДС → Рабочее поле ДДС → Поле со строкой сообщений → Рабочее поле карточки ДДС → Рабочее поле для заполнения статуса (при выборе Поселение Вороновское) → Статус ПРИНЯТО / НЕ ПРИНЯТО формируется выбором из двух статусов, остальные поля заполняются вручную → При нажатии карандашика можно проставлять новые статусы (НАЧАЛО РЕАГИРОВАНИЯ / ОТКАЗ ОТ ВЫПОЛНЕНИЯ РАБОТ / РАБОТЫ ЗАВЕРШЕНЫ) и комментарии».
- Карточка 112: «В поле ЧТО СЛУЧИЛОСЬ выбирается сценарий (их очень много). К каждому сценарию подтягиваются ТЭГИ, где оператор выбирает необходимую информацию. После выбора информации АВТОМАТИЧЕСКИ ПОДТЯГИВАЮТСЯ СЛУЖБЫ, которые можно дополнительно подтягивать вручную. **Красный цвет поля говорит о том, что время набора карточки превышено**».

### 1.4. Работа диспетчера ДДС со статусами (`image7–image20.png`)
Плитка своей службы (в примере «Поселение Во…» = ДДС поселения Вороновское) имеет **карандаш** в правом верхнем углу.

1. **Клик по карандашу** → карточка затемняется, над панелью служб появляется белая строка ввода (`image8.png`): выпадающий список **«Статус»** | поле **«Номер наряда»** | поле **«Комментарий»** | кнопки ✓ (сохранить) и × (отмена).
2. **Первый статус** — выбор из двух: **«Принята» / «Не принята»**. Пример (`image9.png`): «Принята», номер наряда «23», комментарий «Отправлн сантехник для перекрытия воды». Остальные поля — ручной ввод.
3. После сохранения плитка показывает «11:23 Принята» и становится синей. Клик по стрелке ^ открывает **синий попап истории** (`image10.png`): заголовок «Поселение Вороновское ×», строки «оп. 0 › 17.09.2026 11:14:04 Добавлена», «› 11:19:24 Получена службой», «› 11:23:21 Принята › Отправлн сантехник для перекрытия воды».
4. **Следующие статусы** через карандаш (`image14.png`): выпадающий список «Прибытие / Отказ от выполнения работ / Работы завершены» (набор зависит от текущего статуса; «Начало реагирования» появляется после «Принята»). Номер наряда подставляется из предыдущего шага.
5. **Полная цепочка из примера** (`image12`, `16`, `18`, `20.png`):

| Время | Статус | Комментарий |
|---|---|---|
| 11:14:04 | Добавлена | — (автоматически, карточка создана в 112) |
| 11:19:24 | Получена службой | — (автоматически при открытии в ДДС) |
| 11:23:21 | Принята | Отправлн сантехник для перекрытия воды |
| 11:29:04 | Начало реагирования | Сантехники приступили к работе по перекрытию воды в доме |
| 11:32:13 | Прибытие | Дополнительно прибыли рабочие |
| 11:33:40 | Проведение работ | Работы ведутся |
| 11:34:51 | Работы завершены | Работы завершены |

Альтернативная ветка: «Не принята» (на первом шаге) или «Отказ от выполнения работ» (на любом шаге после принятия).

**Вывод для тренажёра:** действия диспетчера ДДС = последовательность записей {статус, номер наряда, комментарий, время}. Это и есть предмет оценки: корректный порядок статусов, наличие обязательных комментариев, регламентность и грамотность текста, время от «Получена службой» до «Принята».

### 2.2. Выбор типа и опросная карта (`card112/image4`, `7`, `9`; `card112_v2/image8`, `16`, `24`, `31`, `39`)
- Ввод в «что случилось?» открывает выпадающий список типов (`card112_v2/image8.png`: Помощь службам, Природная стихия, Прочие происшествия, Радиация, Разбитый градусник…). Полный список типов — в «КАРТОЧКА 112.docx» (52 значения, см. п. 4.1).
