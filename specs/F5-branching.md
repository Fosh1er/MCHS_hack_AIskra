## 1. Пункт плана
> **F5. Ветвящиеся сценарии.** Ситуация развивается по решениям оператора и диспетчера. Не спросил адрес вовремя — огонь перекинулся на соседнюю квартиру. Дал инструкцию «закройте дверь, не пользуйтесь лифтом» — люди эвакуировались. Не отправил скорую при признаках остановки дыхания — исход трагический. Итог виден в конце звонка и в разборе: какая развилка к нему привела и что было бы при другом решении.

## 4. Решения
См. [ADR-0014](../docs/adr/0014-branching-scenarios.md). Коротко:
- **Граф ситуации — в YAML-шаблоне, модель его не строит.** Сценарий хранит копию шаблона с подставленной легендой (`scenarios.branching`): правка каталога не меняет утверждённые сценарии и прошедшие звонки.
- **Путь — чистая функция фактов с отметками времени** (что и когда сказал оператор, что сообщил заявитель, когда сохранена карточка и с какими службами, статусы ДДС). Шаг по ходу звонка и пересчёт целиком дают один путь, поэтому итог в звонке, в оценке и в докладе бригады совпадает.
- **Условия перехода:** `said` (инструкция из словаря шаблона, с отсечкой отрицаний для вредных советов), `asked` (тема сообщена), `act` (действие модификатора), `after_s`, `card_by_s` + `service`, `dds`, `ended`. Условия складываются через «и», срабатывает первый подходящий переход по порядку. У каждого неконечного узла есть переход только по времени, поэтому ситуация не «застывает» без действий оператора.
- **Развилки — реальные обязанности оператора 112:** быстро получить адрес и отправить карточку нужным службам (ПП РФ № 1931: 75 с), дать заявителю инструкцию по официальной памятке, пока едет помощь, и не дать вредного совета («откройте окна» при пожаре, «вытащите из машины» при ДТП).
- **Итоги и вес:** `favorable / partial / adverse / tragic` → 100 / 60 / 30 / 0 баллов, вес по умолчанию 0 (информативно), как у блока «Работа с заявителем».

## 5. Критерии приёмки
- [x] 4 шаблона, в каждом все итоги достижимы, тексты инструкций со ссылками на источники (`test_catalog_is_valid_and_sized`, `test_every_node_and_outcome_reachable_and_forks_matter`).
- [x] Выключенное ветвление → прежние тесты зелёные без изменений (`make be-check`: все прежние тесты проходят, правки в них — только сигнатура фейка `pick_incident`).
- [x] На демо видно: разное решение → разный итог за один звонок не длиннее 3 минут. Проверено на стенде: «Запах газа», звонок 2:40 → «частично благоприятный» (карточка позже 150 с); 40 с молчания → реплика «сейчас свет включу» по таймеру.

## 6. Отклонения, долги, открытые вопросы
- **RF5-10 (P2)** — редактор графа, импорт и экспорт YAML не сделаны. Шаблоны правятся в `branch_templates.yaml`, при старте их проверяет `validate_graph`.
- **RF5-04:** путь меняет доклад старшего группы, но не набор статусов ДДС. Запроса дополнительных сил в АРМ ДДС нет, поэтому «прошу дополнительные силы» звучит только в докладе.
- **Условия `dds`** движок поддерживает, но в шаблонах MVP они не используются: итог решает работа оператора 112, а занятие «только 112» без ДДС не должно зависать.
- **Переходы по времени** («заявительница пошла к выключателю на 40-й секунде») — учебные допущения, они помечены в разборе.
- **Генерация формулировок моделью (RF5-09)** проверена на модели-заглушке. С настоящей моделью не проверялась: нет ключа.
- **F4-07 (события для движка профиля):** узел сдвигает уровень ECCS через `escalate`, отдельных кодов событий профиля нет.
- **Промпт модификатора:** блок «что происходит сейчас» дописывается к `applicant_actor/v3`, новой версии промпта модификатора нет. Без профиля используется новый `v4`.
