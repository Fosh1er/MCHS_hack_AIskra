## 1. Цель
Зафиксировать единую модель данных тренажёра и загрузить справочники заказчика так, чтобы следующие пункты опирались на них без переделок:
- карточка 112 (1.1);
- адрес (1.2);
- автоподбор служб (1.5);
- ДДС (2.x);
- генерация и оценка (3.x);
- занятия и отчёты (4.x).

### 2.2. Справочник служб (`СЛУЖБЫ 112.docx`, 55 скриншотов)
- **Распознано OCR** (`data/raw/services_ocr_2026-09-17.json`): ~190 записей. Из них ~150 — ДДС районов, поселений и префектур в виде «Поселение <район> (ДДС района … города Москвы)».
- **Выверенный справочник — 221 служба:**
  - 54 городские, федеральные и экстренные (`services_core.yaml`). Если расшифровки нет на скриншотах, стоит `confirmed: false`;
  - 146 ДДС районов и поселений;
  - 11 ДДС префектур (включая общую ТиНАО);
  - 10 ГБУ «Автомобильные дороги» округов (`services_territorial.yaml`, генератор `data/tools/build_territorial.py`).
- **Сверка названий:** 145 из 146 районных ДДС найдены на скриншотах заказчика. Одна (Мосрентген) достроена: на скриншоте OCR исказил кавычки.
- **Особенности именования у заказчика** сохранены как есть: «Поселение Бескудниково» — район Бескудниковский, «Упр. района Вешняки», «Поселение Ивановский», «Поселение Преображенский».
- **Телефонов служб в данных заказчика нет.** Для симулятора импорт генерирует **синтетические** детерминированные номера `+7 (495) 000-XX-XX` с флагом `phone_synthetic` (152-ФЗ, учебные данные).

### 2.3. Округа и районы Москвы
- **Официальное деление на 2026 год** (Википедия, `data/raw/moscow_districts_wikipedia_2026-09-26.json`): после реформы 2024 года ТиНАО разбит на 8 районов, район Внуково перенесён в НАО.
- **Номенклатура заказчика** (скриншоты стенда 17.09.2026: «(ТАО, Вороновское)», «Поселение Вороновское») — старая: 125 районов (Внуково — в ЗАО) + 21 поселение ТиНАО (НАО — 11, ТАО — 10). ДДС в системе заказчика привязаны именно к ним.
- **Решение:** справочник районов = номенклатура заказчика (146 записей), с кодами-транслитами и алиасами «ё/е» (Савёлки ~ Савелки). Официальный список сохранён для сверки ([ADR-0009](../docs/adr/0009-dictionaries-storage.md)).
- **Округа** — 12 административных + «МО» (Московская область), как в выпадающем списке АРМ. У НАО и ТАО общая префектура ТиНАО.

### 2.5. Типы «Что случилось?» (`КАРТОЧКА 112.docx`, 51 тип)
Каждый тип привязан к группе классификатора, при необходимости — с фильтром по признаку 1. Например:
- «Природная стихия» — группа 7, признак «Природная стихия»;
- «Скопление воды» — группа 7, признак «Скопление воды»;
- «Разбитый градусник» — группа 11, признак «Градусник».

Кроме того:
- 17 служебных типов без реагирования: справки, «Ошибочно набран номер», «Тестовый вызов» и т.п.;
- синонимы для поиска (101 ↔ пожар, 103 ↔ «вызов 03»);
- «частые» плашки — по скриншоту стенда, «значимые типы» — по инструкции.

Все фильтры признаков найдены в классификаторе: импорт это проверяет.

## 3. Логическая модель данных

```
dict_incident_groups 1─* dict_incident_types 1─* dict_routing *─1 dict_service_columns ··· dict_services
dict_okrugs 1─* dict_districts ··· dict_services (ДДС района)          dict_card_types · dict_enums · dict_import_runs

users *─* groups (group_members: роль, профиль ДДС)
scenarios ─→ dict_incident_types        training_sessions ─→ users(teacher), groups
assignments ─→ training_sessions, scenarios, users(student)   (роль 112 | dds, профиль ДДС)
incident_cards ─→ sessions, assignments, scenarios; payload = IncidentCardData
card_services ─→ incident_cards, dict_services    card_service_statuses (история: статус, № наряда, комментарий)
dds_queue_items ─→ incident_cards, dict_services, assignments   (таймер ожидания от enqueued_at, #709)
action_events ─→ sessions, assignments, cards   (append-only; client_event_id — идемпотентность)
assessments ─→ assignments, cards;  expert_overrides ─→ assessments (причина обязательна)
reports ─→ training_sessions        audit_log (колонки как в разделе «Аудит» АРМ)
```

## 4. Структура карточки 112 (`incidents/domain/card.py`)
`IncidentCardData` — типизированная версия JSON-эталона (docs/brief/03 §4):
- `phones` — `aon`, `provided`, `on_site`, `foreign`;
- `channel`;
- `applicant` — `name`, `status` (6 значений), `foreign_language`;
- `victims` — `has`, `count`;
- `card_types`, `incident_types`, `questionnaire`, `card_flags`;
- `address` — 18 полей, включая коды округа и района;
- `description`, `services`;
- `flags` — `no_contact`, `call_dropped`, `refusal_103`, ЧС, ЧП.

Инварианты:
- описание ≤ 1999 символов;
- количество пострадавших ≥ 0 и только при «Есть»;
- отказ от реагирования — только для 103;
- `ambulance_excerpt` — первые 100 символов (что увидит служба 03).

## 5. Импорт справочников
**Команда** `ImportDictionaries`:
- CLI: `uv run python -m aiskra.cli import-dictionaries`;
- HTTP: `POST /api/v1/dictionaries/import` — только администратор (право `dictionaries.import`), запись «Импорт справочников» в аудит.

**Шаги:**
1. Чтение xlsx (openpyxl), разбор доменными правилами.
2. Проверка раскладки колонок по `classifier_columns.yaml`.
3. Проверка перекрёстных ссылок: колонки ↔ службы ↔ признаки, районы ↔ округа ↔ ДДС, типы ↔ группы ↔ признаки.
4. Одна транзакция:
   - upsert по естественным ключам;
   - мягкая деактивация пропавших типов, служб и районов (`active=false`), чтобы не ломать ссылки сценариев и карточек;
   - перезапись матрицы, типов карточки и перечислений;
   - запись в `dict_import_runs`.

**Отчёт:** счётчики, деактивации, предупреждения о данных заказчика.

**Идемпотентность:** повторный импорт даёт то же состояние (проверено тестом и на PostgreSQL).
