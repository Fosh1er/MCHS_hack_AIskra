# 5.3 — Обучение интерфейсу для нового обучающегося

- **Приоритет:** P1 · **Статус:** ✅ реализовано
- **Ветка:** `feat/5.3-onboarding` · **Решения:** раздел 4 ниже (без отдельного ADR)
- **Зависит от:** 0.3 (вход, права), 1.1–1.3 (АРМ-112), 2.1–2.2 (АРМ ДДС), 5.1 (кабинет обучающегося) · **Используется в:** 7.4 (демо)

## 1. Пункт плана
> Пункта нет в [плане работ](../docs/brief/02_План_работ.md), он добавлен по запросу команды 28.09. Близкие пункты: 5.1 (кабинет обучающегося, «справочная база») и 6.3 (UX).
>
> **Запрос:** для только что созданных обучающихся — пошаговое знакомство с интерфейсом («роадмап по кнопкам»): что где находится и за что отвечает, с возможностью пропустить инструкцию.

**Зачем.** ТЗ, роль «Обучающийся», требует «справочную базу (инструкции, памятка)». Эмулятор копирует АРМ-112 и АРМ ДДС: плотный интерфейс, много кнопок без подписей, горячие клавиши. Новичок, которого посадили за тренажёр без инструктажа, тратит первое занятие на поиск кнопок. Результат такого занятия говорит не о навыке, а о незнании интерфейса. Встроенная подсказка по экранам снимает этот шум с оценки и разгружает преподавателя.

## 4. Решения
- **Прогресс — на сервере, в `users.onboarding`, а не в `localStorage`.** Обучающиеся садятся за разные АРМ класса. Локальная отметка показывала бы инструкцию заново на каждом компьютере, а на уже знакомом компьютере не показала бы её новому человеку. «Новый пользователь» — свойство учётки, а не браузера. Поле JSON (`{dismissed, seen[]}`) в таблице `users`, отдельная таблица не нужна. Резервная копия (5.2) выгружает `users` целиком, поле попадает в копию само.
- **Содержимое инструкций — на фронтенде** (`tours.ts`), сервер хранит только идентификаторы пройденных экранов. Тексты привязаны к разметке экранов и меняются вместе с ней. Сервер проверяет только формат идентификатора (`^[a-z0-9-]{1,40}$`, не больше 50 экранов), чтобы поле не росло бесконтрольно.
- **Не аудит.** Отметка «экран пройден» — настройка интерфейса, а не значимое действие (ТЗ 10.4 требует аудита действий с данными и учётками). В журнал аудита не пишется, чтобы не засорять его.
- **Своя подсветка без библиотеки.** Затемнение с «окном» — четыре полупрозрачные полосы вокруг элемента и рамка; подсказка — под, над или сбоку. Сначала было «окно» из одной рамки с тенью `0 0 0 9999px`, но над таймером карточки 112 (перерисовывается каждую секунду) Chromium её не рисовал — найдено при проверке в браузере. Внешняя библиотека (react-joyride, driver.js) — лишняя зависимость в изолированном контуре и чужие стили, а нужно ~200 строк.
- **Страница сама решает, когда показать.** `useScreenTour(id, ready)` запускает инструкцию, когда данные экрана загружены (`ready`), иначе подсвечивать нечего. Первый показанный экран начинается с обзора `WELCOME`, где бы обучающийся ни вошёл (журнал 112 на десктопе, кабинет на телефоне).
- **Пауза таймера карточки — на сервере, а не только на экране.** Время заполнения (`processing_ms`) считает сервер, от него зависят автооценка, аналитика «норматив / факт», допуск и мониторинг; заморозить только цифры на экране значило бы штрафовать новичка за чтение подсказок. Чтобы пауза не стала лазейкой «остановить время», она: только у черновика своей карточки (у ДДС — пока нет решения «Принята / Не принята»); всего не больше 10 минут на таймер (пауз может быть несколько: подсказки реестра ДДС, потом карточки); каждая пишется в аудит с длительностью; ставится только при **автоматическом** первом показе подсказок — ручной повтор кнопкой «?» таймер не останавливает. Сохранение во время паузы завершает её.
- **Клики по странице во время инструкции заблокированы** прозрачным слоем. Подсветка объясняет, а не ведёт за руку: случайный клик не должен сохранить карточку или сменить статус.

## 5. Критерии приёмки
- [x] Новый обучающийся входит → обзор маршрута, затем подсветка элементов журнала 112 по шагам; «Далее», «Назад», счётчик шагов.
- [x] «Пропустить обучение» на любом шаге → больше не показывается ни на одном экране, в том числе после повторного входа и на другом компьютере.
- [x] Пройденный экран не показывается снова; непройденный — показывается при первом открытии.
- [x] Кнопка «обучение» в шапке АРМ и «?» на панели карточки повторяют инструкцию текущего экрана (и после «пропустить обучение»); «пройти обучение заново» в кабинете сбрасывает прогресс.
- [x] Преподаватель и администратор автоматически инструкцию не видят.
- [x] Esc во время инструкции на карточке 112 не закрывает карточку.
- [x] Пока подсказки по новой карточке 112 показаны впервые, таймер стоит; время заполнения в автооценке — без времени подсказок.
- [x] Пока впервые показаны подсказки реестра или карточки ДДС, таймеры ожидания решения стоят; время реакции — без паузы.
- [x] `make be-check`, `make fe-build` зелёные.

## 6. Отклонения, долги, открытые вопросы
- Инструкции для преподавателя (пульт, банк сценариев, отчёт) не сделаны — по запросу только для обучающихся. Механизм общий: достаточно добавить описание экрана в `tours.ts` и вызвать `useScreenTour` на странице.
- Пауза ДДС общая для строки «карточка × служба»: если за одну службу работают двое и один из них впервые читает подсказки реестра, таймеры очереди стоят и у второго. На занятиях у каждого диспетчера своя служба, поэтому оставлено так.
- Автотестов фронтенда в проекте нет (см. долг 1.1): поведение подсветки проверено вручную в браузере, серверная часть — тестами.
- Тексты подсказок написаны командой по инструкции «Работа на АРМ-112» и скриншотам (docs/brief/03, 04). Методистам заказчика стоит их вычитать.
