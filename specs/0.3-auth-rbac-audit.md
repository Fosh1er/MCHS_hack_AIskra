## 4. Решения
- **Сессии на сервере + HttpOnly-cookie**, а не JWT: мгновенный отзыв, нет токена в JavaScript. Один источник с nginx → нет CORS.
- **scrypt из стандартной библиотеки:** офлайн-контур, без новых зависимостей.
- **Права в общем ядре** (`shared/security.py`) и **порт аудита** (`shared/audit.py`): модули проверяют права и пишут аудит, не завися от `identity` и `audit`.
- **Запрет по умолчанию** в `main.py` и тест по всем маршрутам OpenAPI: забытая проверка не приводит к открытому эндпоинту.
- **Ключи поиска нормализуются в Python** (`shared/text.py`), а не `lower()` СУБД. На временном кластере PostgreSQL с локалью `C` поиск «ИВАНОВ» не находил «Иванов».
- Подробности — [ADR-0010](../docs/adr/0010-auth-rbac-audit.md).

## 5. Критерии приёмки
- [x] Вход с неверным паролем и с несуществующим логином → 401 с одинаковым сообщением, обе попытки в аудите.
- [x] После 5 неудачных попыток (в тестах — 3) вход закрыт даже с верным паролем; событие «Временная блокировка» в аудите.

- [x] Блокировка пользователя и сброс пароля отзывают его активные сессии; смена роли действует без повторного входа.

## 6. Отклонения, долги, открытые вопросы
- **Второй фактор (TOTP)** для администратора и преподавателя — идея из нашего дизайна, в ТЗ «многоуровневая аутентификация» без уточнения. Сейчас уровни такие: пароль + номер АРМ + права роли + серверная сессия. Вопрос к заказчику: нужен ли второй фактор?
- **LDAP/AD** (ТЗ 10.7, опционально) — не делали; порт `PasswordHasher` / команда `Login` позволяют добавить адаптер.
- **Срок хранения журнала:** записи не удаляются вообще. Архивирование старше N месяцев (при N ≥ 6) — вместе с бэкапом в 5.2.
- **Экран «Пользователи»** → ➡️ 5.2 (API готово).
- **Номер АРМ необязательный:** на стенде ДДС 2026 поля нет, в инструкции 112 оно есть. Вопрос к заказчику: обязателен ли номер АРМ для роли 112?
- **Лишние сессии:** истёкшие записи `auth_sessions` не чистятся. Объём небольшой (одна запись на вход); очистка — вместе с обслуживанием БД в 5.2.
