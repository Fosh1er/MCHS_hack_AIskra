# 4.7 — Отзыв преподавателя по занятию с черновиком от ИИ

- **Приоритет:** P1 (сверх плана; запрос команды 29.09) · **Статус:** ✅ (с настоящей моделью вживую не проверено — ключа нет)
- **Ветка:** `feat/4.7-teacher-feedback` · **Решения:** ADR-0003 (ИИ за портом), ADR-0006 (кеш)
- **База кода:** `backend/src/aiskra/modules/assessment/` (`domain/feedback.py`, `application/queries/feedback.py`, `application/commands/feedback.py`), фронт `frontend/src/pages/teacher/SessionReportPage.tsx`, `frontend/src/pages/student/`
- **Зависит от:** [3.4](3.4-assessment.md), [4.3](4.3-reports.md), [5.1](5.1-student-cabinet.md) · **Используется в:** [3.5](3.5-validation.md) (насколько преподаватели правят черновики)

## 1. Задача
> Учитель, когда подробнее просматривает результат урока конкретного студента, получает от ИИ предложение отзыва: обратная связь по уроку, что нужно подтянуть. Преподаватель может отредактировать и оставить такой отзыв. В истории у студента появится отзыв преподавателя.

Основания в требованиях:
- 01 разд. 2.4 и 3.14 — «комментарии обучающимся»;
- 01 разд. 7.3 — «рекомендации обучающемуся»;
- план 4.3 — «комментарий преподавателя… история и прогресс»;
- план 5.1 — «после занятия — свои результаты, разбор ошибок, рекомендации; история».

До 4.7 комментарий был только у экспертной правки одной карточки и только вместе с новым баллом. Отзыва по занятию целиком, без правки балла, не было.

## 2. Требования
| ID | Требование | Источник |
|---|---|---|
| R4.7-01 | Черновик отзыва одному обучающемуся по одному занятию. Строится из фактов занятия: баллы, «зачтено», критерии, замечания, время против норматива. Структура: итог → что получилось → что подтянуть (не больше трёх) → следующий шаг | задача; Hattie & Timperley 2007; Shute 2008 |
| R4.7-02 | Черновик пишет модель задачи `feedback_draft`. Без модели (изолированный контур, `fake`) или при её ошибке черновик строится по правилам из тех же фактов. Интерфейс показывает, кто его составил | ADR-0003; docs/rules/ai.md |
| R4.7-03 | Модель получает только факты, без ФИО. Черновик сам ничего не публикует: обучающийся видит отзыв только после «сохранить» | docs/rules/ai.md («не отдавать модели ПДн»); ТЗ «комментарии обучающимся» дают преподаватели |
| R4.7-04 | Преподаватель правит текст и сохраняет. Повторное сохранение заменяет текст. У пары «занятие + обучающийся» — один действующий отзыв. Каждое сохранение пишется в журнал аудита | ТЗ: значимые действия — в аудит |
| R4.7-05 | Черновик и сохранение доступны только преподавателю, который вёл занятие, и только для его участника. Чужое занятие — 404, обучающийся — 403 | R4.5-07; ADR-0010 |
| R4.7-06 | Обучающийся видит отзыв в «Истории занятий» кабинета и на странице «мои результаты» занятия. Видит только свои отзывы | задача; план 5.1 |

| R4.7-08 | Отзыв виден в отчёте по занятию: отметка у обучающегося, текст в раскрытой строке, колонка в CSV, печать в PDF | план 4.3 |
| R4.7-09 | Сохраняются исходный черновик и его источник. Так видно, насколько преподаватели правят черновики ИИ | 3.5 (валидация качества ИИ) |
| R4.7-10 | Подсказки (5.3, 5.4) рассказывают про отзыв: в отчёте у преподавателя и в истории у обучающегося | 5.3, 5.4 |

## 4. Решения
- **Отзыв — по занятию, а не по карточке.** У карточки уже есть замечания автооценки и комментарий экспертной правки. Не хватало итога по уроку: что в целом получилось и что делать дальше.
- **Структура — по исследованиям обратной связи (раздел 7).** Три вопроса Hattie & Timperley: как прошло, что получилось и что подтянуть, что дальше. По Shute — не больше трёх пунктов «подтянуть», конкретный пример из своих карточек, без сравнения с группой.
- **ИИ пишет формулировки, но не выбирает факты.** Что подтянуть, в каком порядке, какие номера карточек и советы — считают правила. Модель получает готовые факты и только превращает их в связный текст. Отсюда два следствия:
  - без модели черновик тот же по смыслу;
  - модели труднее придумать то, чего не было.
- **В «подтянуть» попадают и мелкие потери.** Раньше рекомендации строились только по критериям ниже 85 %. На стенде у Новикова средний балл 96,7, и «подтянуть» оставалось пустым, хотя в карточках были конкретные промахи: номер дома, газификация, вопрос о пострадавших. Теперь в «подтянуть» попадает всё, что меньше 100 %, от худшего, не больше трёх пунктов. Следующий шаг различает серьёзное («сосредоточьтесь на одном») и мелкое («уберите мелкие неточности — и можно сложнее»).
- **Черновик — не публикация.** Черновик не сохраняется. Обучающийся видит только то, что преподаватель сохранил: автор отзыва — преподаватель (ТЗ: «комментарии обучающимся»). Замечания могут содержать цитаты из текста обучающегося, то есть через них возможна инъекция в промпт. Последняя защита от неё — человек, который читает черновик.
- **Один действующий отзыв, история — в аудите.** Обучающемуся не нужны версии, ему нужен актуальный текст. Каждое сохранение пишется в журнал аудита, там видно, кто и когда менял.
- **Модуль `assessment`, без межмодульных связей.** Название и время начала занятия копируются в отзыв. Поэтому история обучающегося (`/my/feedback`) не обращается к `training`, а фронт сопоставляет отзывы с занятиями по `session_id`.
- **Право — `lessons.conduct` и только своё занятие.** Отзыв — действие того, кто вёл урок. Чужой преподаватель получает 404, как в аналитике (R4.5-07).

## 5. Критерии приёмки
- [x] В раскрытой строке обучающегося в отчёте кнопка «предложить отзыв» даёт черновик: итог, что получилось, что подтянуть, следующий шаг.
- [x] Без модели черновик строится по правилам и помечен «черновик по правилам»; при ошибке модели — предупреждение.
- [x] Преподаватель правит текст и сохраняет. Отметка «отзыв» у ФИО, текст — в отчёте, CSV и PDF.
- [x] Обучающийся видит отзыв под занятием в «Истории занятий» и на странице «мои результаты»; чужих отзывов не видит.
- [x] Следующий черновик этому обучающемуся показывает прошлый отзыв и «было → стало» по прошлым «подтянуть».
- [x] Сохранение — в журнале аудита; обучающийся и чужой преподаватель не могут писать отзыв.
- [x] Телефон 375 px: отзыв и редактор по ширине экрана, страница без горизонтальной прокрутки.

## 6. Отклонения, долги, открытые вопросы
- **С настоящей моделью вживую не проверено.** Ключа OpenRouter на стенде нет. Путь модели проверен на `FakeLLM` с ответом модели и с ошибкой. Промпт `v1` стоит прогнать на стенде с ключом.
- **Метрика правки черновиков** (`similarity`) сохраняется, но экрана нет. Место ей — «Достоверность» (3.5), рядом с согласием автооценки и эксперта.
- **Сознательно не делали** — раздел 7.2.

## 7. Исследование
### 7.1. Какой должна быть обратная связь
| Источник | Что берём | Где в решении |
|---|---|---|
| [Hattie & Timperley, 2007. The Power of Feedback](https://journals.sagepub.com/doi/abs/10.3102/003465430298487), Review of Educational Research 77(1) | Хорошая обратная связь отвечает на три вопроса: куда иду, как иду, что дальше. Полезнее всего отзыв об успешности выполнения задачи и о приёмах работы; похвала «вы молодец» почти не работает | разделы отзыва; «следующий шаг»; «С прошлого отзыва» — проверка прошлого «что дальше»; в промпте — без оценок личности |
| [Shute, 2008. Focus on Formative Feedback](https://journals.sagepub.com/doi/10.3102/0034654307313795), Review of Educational Research 78(1) | Конкретно, ясно, небольшими порциями; объяснять «что, как и почему»; не сравнивать с другими обучающимися | до трёх пунктов «подтянуть»; пример замечания и номера карточек; совет «как правильно»; сравнения с группой нет, хотя профиль (4.5) его считает |
| [Making AI-Generated Feedback Matter, arXiv 2608.11625](https://arxiv.org/abs/2608.11625) — 13 тыс. студентов | Отзыв ИИ сам по себе мало что даёт: его применяют, когда есть действие, к которому он ведёт. Главное — устройство процесса | «Следующий шаг» — одно действие; преподаватель видит прошлый отзыв и проверяет, выполнен ли шаг |
| [LLM feedback in Higher Education, arXiv 2602.02519](https://arxiv.org/abs/2602.02519) | Модель пишет хороший отзыв, только если у неё есть чёткий контекст и рубрика | модель получает готовые факты и советы из справочника, а не сырую карточку |
| ГОСТ Р 22.7.01-2021, п. 3.12.3 ([docs/research](../docs/research/Подготовка_персонала_112_и_ЕДДС.md)) | Подведение итогов с разбором характерных недостатков | разбор группы уже есть (4.5); отзыв — то же, но лично обучающемуся |

### 7.2. Что нужно, а что излишне
| Возможность | Решение | Почему |
|---|---|---|
| Черновик от ИИ по фактам занятия | **делаем** | суть задачи: преподавателю не писать с нуля |
| Правка и сохранение преподавателем | **делаем** | автор отзыва — преподаватель; ИИ может ошибиться или поддаться инъекции через текст обучающегося |
| Черновик без модели | **делаем** | изолированный контур заказчика по умолчанию без модели (ADR-0003) |
| Отзыв в истории и в «мои результаты» | **делаем** | задача; план 5.1 |
| Связь с прошлым отзывом | **делаем** | «что дальше» имеет смысл, только если следующий отзыв это проверяет |
| Отметка, колонка CSV, печать | **делаем** | отчёт 4.3 выгружается для отчётности, отзыв — его часть |
| Отправка отзыва ИИ без преподавателя | излишне | ТЗ: комментарии обучающимся даёт преподаватель; ответственность за текст — на человеке |
| Отзыв к каждой карточке | излишне | уже есть: замечания автооценки и комментарий экспертной правки |
| Сравнение с группой в отзыве | излишне, даже вредно | Shute: сравнение с другими снижает мотивацию; сравнение остаётся в профиле для преподавателя |
| Изменение балла из отзыва | излишне | балл меняет только экспертная правка с аудитом (4.3) |
| Ответ обучающегося, переписка | излишне | вне ТЗ; вопросы обсуждаются на разборе (ГОСТ Р 22.7.01) |
| Уведомления по почте | излишне | изолированный контур без почты; отзыв виден в кабинете |
| Версии отзыва для обучающегося | излишне | обучающемуся нужен актуальный текст; история правок — в журнале аудита |
