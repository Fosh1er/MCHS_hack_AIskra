## 1. Пункт плана
> Пункта нет в [плане работ](../docs/brief/02_План_работ.md), он добавлен по запросу команды 29.09. Близкие пункты:
> - 5.3 — подсказки по кнопкам для обучающегося;
> - 4.1–4.6 — кабинет преподавателя;
> - 6.3 — UX.
>
> **Запрос:** «Нужно добавить подсказки, как для студента, но только для преподавателя. Исследуй, какие ему будут нужны, а какие излишне».

**Зачем.** В ТЗ у преподавателя больше всего функций (01 разд. 2.4): банк сценариев с утверждением, занятия с ролями и темпом, мониторинг, автооценка и экспертная правка, отчёты, аналитика, допуск.

Портрет из дизайн-концепции команды (роль «Преподаватель», вне репозитория): «часто сам бывший оператор или диспетчер… хорошо знает регламент, но не аналитик и не айтишник». Его цели: занятие — за ≤ 5 минут, разбор — за ≤ 10 минут.

Без подсказок новый преподаватель рискует:
- начать занятие без нужных ролей;
- не утвердить сценарии и удивиться черновикам в банке;
- не найти разбор разговора и экспертную правку;
- неверно прочитать тепловую карту или информативный критерий.

## 4. Решения
1. **Механизм 5.3 без изменений в сути.** Прогресс остаётся в `users.onboarding`, подсветка — в `Tour.tsx`, экраны регистрируются через `useScreenTour`. Добавляются только:
   - аудитория экрана (чьи подсказки);
   - свой обзор для преподавателя.
2. **Аудитория решается на сервере по правам** (`audience`), а у экрана на фронте записано, для кого он. Так подсказки обучающегося не всплывают у преподавателя в журнале 112, а подсказки преподавателя — у администратора на странице материалов. Роль строкой не проверяется (AGENTS.md).
3. **Форма «Новое занятие» — отдельный экран подсказок.** Она открывается по кнопке и содержит самое неочевидное: тип, источник карточек, роли и службы, подбор по слабым местам, нормативы. Пока форма закрыта, её поля на экране отсутствуют, а шаги без цели пропускаются. Поэтому подсказки формы запускаются, когда форма появилась.
4. **Скрытые кнопки объясняются шагом на видимом контейнере.** Например, «правка» и «разговор» появляются только в раскрытой строке отчёта. Иначе шаг пропустился бы.
5. **Отметки одним запросом:** `POST /auth/onboarding {action: seen, tours: [...]}`. Старый формат `{tour}` принимается.

## 6. Отклонения, долги, открытые вопросы
- Подсказки для проверки карточек преподавателем в АРМ («проверена», «вернуть на доработку») — только одной строкой обзора. Отдельный тур по АРМ для преподавателя — излишне: это одно действие в знакомом ему интерфейсе.
- Экраны, которые появятся позже (пульт инструктора T-41…T-44 из дизайна), подключаются так же: описание в `TOURS`, `useScreenTour`, аудитория `teacher`.

## 7. Детали

### 7.1. Какие подсказки нужны, а какие излишни
Критерии отбора:
- экран на главном пути преподавателя: подготовить → провести → разобрать;
- на экране есть необратимое действие;
- есть спрятанные приёмы (клик по строке, по ФИО, выбор строк);
- есть цифры, которые человек без аналитической подготовки прочитает неверно.

**Не объясняем:** регламент 112 и ДДС, очевидное (листание, печать, назад), экраны, которые объясняют себя сами.

| Экран | Нужны? | Почему | Шагов |
|---|---|---|---|
| Пульт (`/teacher`) + обзор маршрута | да | первый экран; куда идти за чем; инсайты группы — тема инструктажа | обзор 2 + 3 |
| Банк сценариев | да | в занятия идут утверждённые; черновики «на проверке»; что проверить перед «утвердить»; ИИ пишет только речь, тип и службы — правила | 4 |
| Занятия (список) | да, коротко | где создать, где пульт и отчёт | 2 |
| Новое занятие (форма) | да | больше всего неочевидного: тип и роли, источник карточек ДДС, группа, подбор по слабым местам, нормативы ПП № 1931 и темп | 5 |
| Мониторинг занятия | да | «начать» и «завершить» необратимы; как читать плитки (таймер против норматива, состояние заявителя) | 3 |
| Отчёт занятия | да | оценка всех карточек; скрытые «правка» и «разговор»; правка окончательна и в аудите; «отзыв по занятию» с черновиком от ИИ ([4.7](4.7-teacher-feedback.md), тот же шаг, что и правка); тепловая карта и информативный критерий; разбор и выгрузки | 5 |
| Аналитика | да, коротко | норматив и факт по ПП № 1931; клик по ФИО — профиль | 2 |
| Профиль обучающегося | да, коротко | «индивидуальное задание» — неочевидная возможность; готовность и рекомендации | 3 |
| Допуск | да, коротко | шкала Программы подготовки ЕДДС 2023; выбор строк для протокола | 3 |
| Учебные материалы | да, коротко | «использовать в генерации» — выдержки уходят в запрос к ИИ; «видно обучающимся» | 2 |
| Достоверность | **излишне** | нужна методисту, а не для занятий; на странице есть блок «Как читать» | — |
| Протокол допуска | **излишне** | печатная форма, действий нет | — |
| Разбор занятия | **излишне** | карточки с пояснениями, упомянут в подсказках отчёта | — |
| АРМ-112 и АРМ ДДС | **излишне** автоматически | подсказки обучающегося — про заполнение карточки, преподавателю — по кнопке; проверка карточки — строка обзора | — |
