## 4. Решения
- **Очередь — это службы карточки.** Карточка поступает в ДДС в момент сохранения в 112 (`card_services`, статус «Добавлена»). Таблица `dds_queue_items` остаётся для 4.2: там преподаватель будет выпускать системные карточки по расписанию.
- **Поток без ограничений.** Как сказал заказчик (#709), карточки приходят одновременно, тайминг идёт и по текущей, и по ожидающим.

## 5. Критерии приёмки
- [x] Карточка, сохранённая оператором 112 с ДДС района, появляется в реестре этой ДДС с таймером ожидания.
- [x] `make be-check` и `make fe-build` зелёные.

## 6. Отклонения, долги
- 20.10.2026 (ТЗ 2.7, 2.8): реестр раньше фильтровался только по коду службы из адреса — любой обучающийся видел карточки всех занятий этой службы. Теперь на занятии диспетчер видит только свою службу и карточки своего занятия. Вне занятия остаётся свободная практика (демо-стенд, смоук CI): любая служба, но только карточки, не привязанные к занятиям, — карточки занятий код службы в адресе не открывает.
- Темп и состав потока (системные карточки по расписанию) — 4.2.
- Проверено на SQLite; на PostgreSQL — при `docker compose up`.
