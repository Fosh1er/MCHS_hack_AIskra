## 1. Пункт плана
> **0.1. Архитектура и стек — P0**
> - **Фронт работ:** монорепозиторий; backend (REST API + WebSocket для реального времени), frontend (SPA, адаптив), PostgreSQL, контейнеризация (docker compose), абстракция провайдеров ИИ (LLM / STT / TTS) с конфигом эндпоинта; схема данных; OpenAPI.
> - **Документация:** 01_Консолидированные_требования.md разд. 7.4, 8.7, 10; сопроводительная документация → раздел «Компонентная архитектура», «Условия и ограничения».
> - **Материалы:** ТЗ «Форматы данных», «Совместимость», «Требования к решению»; ответы #710, #744–746 (настраиваемый эндпоинт модели, локальное развёртывание).

## 5. Критерии приёмки
- [x] `make be-check` зелёный: ruff, format, mypy --strict, import-linter, pytest.
- [x] `make fe-build` зелёный.
- [x] Офлайн-режим с fake-моделью. Смена модели — только конфигом. Повторный одинаковый запрос отдаётся из кеша (тест).
- [x] Внешний адрес используемого провайдера при `allow_external: false` — ошибка старта (тест).
- [ ] `docker compose up --build` поднимает db, backend (`:8000/docs`) и frontend (`:8080`) — проверить на машине с Docker.
