# 6.2 — Безопасность

- **Приоритет:** P0 · **Статус:** ✅ (nginx с TLS проверен синтаксически — без Docker на машине разработки; запуск — M7)
- **Ветка:** `feat/6.2-security` · **Решения:** [ADR-0010](../docs/adr/0010-auth-rbac-audit.md) (вход, сессии, RBAC, аудит)
- **Опирается на:** [0.3](0.3-auth-rbac-audit.md), [5.2](5.2-admin-panel.md)

## 1. Пункт плана
> **6.2. Безопасность — P0.** TLS (self-signed для локального контура), хеширование паролей, JWT/сессии, RBAC на API, защита от инъекций, хранение журналов ≥6 мес (ретеншн), минимизация ПДн (учебные данные синтетические).

## 2. Требования
| ID | Требование |
|---|---|
| R6.2-01 | TLS на входе (nginx): самоподписанный сертификат создаётся сам, свой — подкладывается томом; HTTP → HTTPS; cookie сессии `Secure` |
| R6.2-02 | Заголовки безопасности: CSP, запрет встраивания чужими сайтами, nosniff, Referrer-Policy, Permissions-Policy, HSTS под TLS; ответы API не кешируются |
| R6.2-03 | Пароли — медленный хеш со солью (scrypt), политика длины, блокировка после неудачных попыток (готово в 0.3) |
| R6.2-04 | Сессии: случайный токен в HttpOnly-cookie `SameSite=Strict`, в БД — только хеш, TTL, отзыв (готово в 0.3); JWT не используется (решение ADR-0010) |
| R6.2-05 | RBAC на API: любой маршрут `/api/v1`, кроме входа, требует сессии — проверяется автоматически по всем маршрутам |
| R6.2-06 | Ограничение подбора паролей с одного IP (в дополнение к блокировке учётки) |
| R6.2-07 | Защита от инъекций: SQL — только параметры; имена в служебном SQL экранируются; XSS — без вставки HTML; загрузки — тип по содержимому, имена файлов безопасны; пути — без обхода каталогов |
| R6.2-08 | Ошибки сервера не раскрывают внутренности: единый ответ 500, подробности — в лог |
| R6.2-09 | Журнал аудита хранится не меньше 6 месяцев: срок хранения — настройка (от 183 дней), очистка старше срока — командой или кнопкой, сама очистка пишется в аудит |
| R6.2-10 | Минимизация ПДн: учебные данные синтетические; во внешние модели уходят только легенды и реплики, не данные учёток; внешние адреса моделей по умолчанию запрещены |
| R6.2-11 | Проверка зависимостей на известные уязвимости |

## 4. Решения
- **TLS на nginx**, а не в uvicorn: один вход, API снаружи недоступен. Самоподписанный сертификат — автоматически, чтобы стенд поднимался одной командой; свой — подкладывается томом.
- **Минимальный срок хранения — в коде**, а не только в настройке: даже прямой вызов очистки не удалит записи моложе 183 дней.
- **Ограничение по IP — в памяти процесса**: API работает одним процессом (ADR-0005); при масштабировании — перенести в Redis.

## 5. Критерии приёмки
- [x] Без входа недоступен ни один маршрут API, кроме входа.
- [x] Подбор пароля ограничен и по учётке, и по адресу.
- [x] Журнал аудита нельзя сократить меньше чем до 6 месяцев.
- [x] Внутренние ошибки не раскрываются клиенту.

## 6. Отклонения, долги
- Запуск `docker compose` с TLS не проверен: на машине разработки нет Docker (M7 — на сервере).
- `react-router` 6.x с двумя средними уязвимостями — не эксплуатируются в SPA без SSR; обновление до v7 — ломающее, отложено.
- Ограничение по IP сбрасывается при перезапуске API.
