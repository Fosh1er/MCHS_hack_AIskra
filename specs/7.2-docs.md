## 1. Пункт плана
> **7.2. ## 4. Как пересобрать
```bash
cd backend
uv run --with python-docx --with pypandoc_binary --with pypdfium2 python ../docs/delivery/build.py
```
Нужен LibreOffice (`soffice`) для PDF. Содержание собирается в два прохода: LibreOffice не обновляет поля Word, поэтому номера страниц берутся из первого PDF и вписываются статически.

## 5. Проверки
`tests/unit/test_delivery_doc.py`: у каждого из 83 требований есть статус в матрице; каждая операция OpenAPI есть в таблице API; каждая таблица БД — в модели данных; в исходнике только известные подстановки; узкие колонки таблиц не рвут слова. Вёрстка проверена по отрисованным страницам PDF (содержание, таблицы, схема).

## 6. Ограничения
- Статусы матрицы — ручная таблица `MATRIX` в `build.py`; при закрытии пункта плана её надо обновить (тест поймает только новое требование без статуса).
- Метрики достоверности ИИ-оценки описаны как методика, чисел нет — честно помечено в документе.
- Перед сдачей пересобрать документ, чтобы статусы 7.3–7.4 и повтор замеров на PostgreSQL попали в матрицу.
