# 3.4 — Автооценка

- **Приоритет:** P0 · **Статус:** ✅ (экспертная правка оценки — 4.3; настройка весов в интерфейсе — 4.2, в API есть)
- **Ветка:** `feat/3.4-assessment` · **Решения:** [ADR-0003](../docs/adr/0003-ports-adapters-ai.md), [ADR-0001](../docs/adr/0001-modular-monolith-clean-architecture.md) (попытка собирается адаптером `aiskra/integration/assessment_sources.py`)
- **Зависит от:** [3.2](3.2-scenario-generation.md) (эталоны), [1.4](1.4-incoming-call.md) и [2.3](2.3-dds-phone.md) (разговоры), [2.2](2.2-dds-card.md) (статусы ДДС) · **Используется в:** 3.5, 4.3

## 1. Пункт плана
> **3.4. Автооценка — P0.** Детерминированная часть: сравнение полей карточки с эталоном (тип — точное/группа, признаки, службы — precision/recall, адрес — нормализованное совпадение, статус заявителя, пострадавшие), тайминг (норматив, отклонение), порядок и полнота статусов ДДС, факт звонков, штрафы за срыв/пропуск; LLM-часть: смысловое соответствие описания легенде, полнота ключевых фактов, регламентность формулировок комментариев, грамматика и орфография; итоговый балл по настраиваемым весам и порогам; объяснение ошибок обучающемуся; инсайты по группе.

## 2. Методы (формулы)
Реализация — `backend/src/aiskra/modules/assessment/domain/scoring.py`. Каждый критерий даёт 0…1 и список ошибок.

**Карточка 112** (эталон — `scenario.reference_card`):

| Критерий | Формула | Вес |
|---|---|---|
| Тип происшествия | точный конечный тип — 1; тот же «Что случилось?» или группа классификатора — 0,5; иначе 0 | 3 |
| Службы | F1 по кодам служб (точность и полнота); отдельное замечание, если нет основной | 2 |
| Адрес | улица (нормализованная: без «ул.», регистра, пунктуации) 0,6 + дом 0,3 + район 0,1 | 2 |
| Признаки опросной карты | F1 по признакам | 1 |
| Заявитель | фамилия 0,5 + статус 0,5 | 1 |
| Пострадавшие | наличие 0,7 + количество 0,3 | 1 |
| Описание: ключевые факты | доля ключевых слов эталона в описании | 1 |
| Полнота опроса | доля тем, уточнённых у заявителя в разговоре: адрес, что случилось, пострадавшие | 1 |
| Время заполнения | 1 в нормативе (80 с); линейно до 0 при тройном нормативе | 1 |
| Описание: смысл (ИИ), грамотность (ИИ) | оценка ИИ-судьи 0…1 | 1 / 0,5 |

**Работа ДДС** (эталон — `scenario.reference_dds`, история `card_service_statuses`, звонки `training_calls`):

| Критерий | Формула | Вес |
|---|---|---|
| Решение | первый статус совпадает с эталоном («Принята») — 1, иначе 0 | 3 |
| Время реакции | от поступления до решения; 1 в нормативе (30 с), до 0 при тройном | 2 |
| Порядок и полнота статусов | (достигнутый шаг + 1) / 5 × (1 или 0,7 при нарушении порядка); «Отказ от выполнения работ» — осознанное завершение | 2 |
| Номер наряда | указан при «Принята» | 1 |
| Комментарии | доля статусов с комментарием | 1 |
| Звонки | доля ожидаемых звонков (старший группы) | 1 |
| Регламентность, грамотность (ИИ) | оценка ИИ-судьи | 1 / 0,5 |

**Итог** = 100 × Σ(балл × вес) / Σ(вес) по проверенным критериям; «зачтено» — от 70. Критерии ИИ без модели — «не проверено», в итог не входят. Веса, норматив и порог можно передать в `POST …/evaluate` (`weights`, `norm_seconds`, `threshold`).

## 6. Отклонения, долги
- Карточка без сценария (заведена вручную) оценивается только по времени — эталона нет.
- Экспертная правка оценки с причиной (`expert_overrides`) — 4.3. Сравнение автооценки с экспертной (достоверность) — 3.5.
