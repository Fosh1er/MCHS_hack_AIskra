# F6.5 — E2E-набор: сквозные сценарии в браузере

- **Приоритет:** P0 · **Статус:** 🟡 сценарии F6.5 п. 1–6 и дефект D8 покрыты (9 тестов, Chromium и Firefox); не покрыты «без рук», перебивание в полигоне, обрыв сети с черновиком карточки
- **Ветка:** `feat/F6-e2e` · **Решения:** ADR-0013 (поток), ADR-0014 (ветвление), ADR-0015 (режимы окружения)
- **Зависит от:** F1, F2, F4, F5, п. 3.6, 4.1–4.7, 5.2 · **Используется в:** F6.4 (CI), баг-баш F6.8

## 1. Пункт плана
> **6.5 E2E-сценарии (Playwright, `tests/e2e/`)**
> 1. Преподаватель: генерирует сценарий → утверждает (полностью и частично); создаёт занятие с профилями и ветвлением; мониторинг → отчёт → отзыв → допуск.
> 2. Оператор 112: входящий → разговор текстом, голосом (fake STT) и без рук; карточка с адресом из справочника → службы → сохранение → оценка с блоком психологии.
> 3. ДДС: очередь → «Принята» с бригадами → звонок старшему → статусы → запись звонка WAV.
> 4. Администратор: пользователи, группы, настройки, резервная копия → восстановление, остановка и запуск подсистем, оповещения.
> 5. Полигон: вход → разговор → озвучка (fake) → перебивание.
> 6. Отказы: модель недоступна → офлайн-ответы; TTS недоступен → голос браузера; обрыв сети → черновик карточки сохраняется и восстанавливается; перезапуск backend посреди занятия.
>
> **D8.** Полигон (`/voice-lab`) не проверен с реальными STT и TTS через nginx → e2e на стенде (F6.5).

## 4. Решения
- **Фронтенд — `vite preview` собранного `dist`**, а не dev-сервер: тот же бандл, что на стенде, без компиляции по запросу (стабильнее по времени); прокси `/api` → backend как у nginx. `make e2e` собирает фронтенд перед прогоном.
- **Заглушка модели в процессе pytest (поток), только stdlib.** Тест сам останавливает и запускает её (отказ модели = закрытый порт) и включает отказ синтеза флагом. На запрос со схемой (адаптер вставляет «Отвечай строго JSON по схеме») заглушка отвечает валидным JSON по этой схеме — генерация легенды, черновик отзыва, ИИ-судья идут «через модель», а не в офлайн.
- **Подготовка данных — через API, проверка — через интерфейс.** Карточка для очереди ДДС и занятие для оператора 112 создаются API: их интерфейс проверяется в своих тестах. Тесты независимы и идут в любом порядке.
- **Учётки отказов и полигона — `load001…003`** (`demo-seed --load-users 3`): у `op1`/`op2` бывают занятия других тестов.
- **Консоль:** ошибка — `pageerror`, `console.error` (кроме «Failed to load resource» — код ответа виден по сети) и ответ API 5xx.

## 7. Отклонения, долги, открытые вопросы
- **D8 через nginx** — не проверено: набор работает через `vite preview`. Следующий шаг — тот же набор против `docker compose` в CI (F6.4, переменная адреса стенда вместо фикстуры).
- **Не покрыто:** разговор «без рук» (V3), перебивание в полигоне, обрыв сети с восстановлением черновика карточки. Синтетический микрофон уже есть — «без рук» добавляется следующим тестом.
- **Реальные STT/TTS/LLM** — вне набора (заглушка); ночной прогон на модели демо-конфига — F6.4.

| Баннер «Есть карточка с заявителем по этому номеру» открывался при каждом повторе сценария банка (тот же номер в легенде) и перекрывал карточку | `pages/card112/Card112Page.tsx` | сам — только при повторном звонке (`CallView.repeat_of`), иначе — кнопка «совпадение» | `e2e/test_teacher.py`, `e2e/test_repeat_calls.py` |
