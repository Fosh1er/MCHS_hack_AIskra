# 3.6 — Эмоциональный голос собеседника и разговор без рук

- **Приоритет:** P1 (этапы V1–V3) / P2 (V4–V5) · **Статус:** 🟡 V1 ✅ (состояние заявителя, озвучка браузером по состоянию); V2 ✅ (серверный синтез; Gemini через OpenRouter вживую не проверен — нет ключа); V3 ✅ (разговор без рук; с настоящим Whisper не проверен — нет модели распознавания на машине разработчика); V4 ✅ (разбор разговора, информативный показатель, мониторинг); V5 ⏳
- **Ветка:** `feat/3.6-emotional-voice` · **Решения:** [ADR-0011](../docs/adr/0011-voice-emotional-caller.md), [исследование](../docs/research/Голос_и_эмоции_заявителя.md)
- **Зависит от:** [1.4](1.4-incoming-call.md) (звонок, голосовой ввод), [2.3](2.3-dds-phone.md) (софтфон ДДС), 3.1 (порты моделей), [3.3](3.3-dialog-agents.md) (ролевые агенты), [5.3](5.3-onboarding.md) (подсказки, пауза таймера)
- **Используется в:** [3.4](3.4-assessment.md) (информативный показатель), [4.2](4.2-sessions.md) (мониторинг), [4.5](4.5-teacher-analytics.md) (разбор), [7.4](7.4-demo.md) (демо)
- **Источник идей:** прототип [zhamilka1/emotional-stt-tts](https://github.com/zhamilka1/emotional-stt-tts), коммит `2dc93c0` от 28.09.2026 — переносим идеи и подобранные значения, код пишем заново (лицензии у прототипа нет).

## 1. Пункт плана
> Пункта нет в [плане работ](../docs/brief/02_План_работ.md), он добавлен по запросу команды 29.09. Близкие пункты:
> - 1.4 «режим голоса: TTS реплик заявителя + STT вопросов оператора»;
> - 3.3 «эмоциональный фон по сложности»;
> - 3.1 «`TTSProvider` (Silero/Piper локально / внешний)»;
> - 2.3 «ИИ-„старший группы“ отвечает текстом/голосом».
>
> **Запрос:** «добавить в проект голос из репозитория emotional-stt-tts».

**Зачем.**

*Что сейчас:*
- эмоция заявителя — строка в промпте по сложности («в панике»), она не меняется от поведения оператора;
- офлайн-ответ эмоцию не учитывает;
- голос браузера ровный;
- оператор, который грубит паникующему заявителю, и оператор, который его успокоил, получают одного и того же собеседника.

*Что даёт пункт.* Профстандарт 12.002 (A/01) и программы подготовки 112 требуют работать с психологическим состоянием заявителя (см. [исследование подготовки](../docs/research/Подготовка_персонала_112_и_ЕДДС.md), строка 7 «устойчивость к сложному заявителю»). Пункт превращает эмоцию в механику тренажёра:
- заявитель реагирует на тон оператора;
- голос передаёт состояние;
- преподаватель видит, что повлияло.

## 2. Требования
Этапы идут по ценности и риску. Каждый этап самостоятелен и выключается конфигом.

### V1 — Эмоциональное состояние заявителя (сервер), P1
| ID | Требование | Источник |
|---|---|---|
| R3.6-01 | У звонка с заявителем есть состояние: эмоция (перечень), напряжение 0–10, доверие 0–10, готовность отвечать 0–10. Хранится за звонком и переживает перезагрузку страницы | 3.3 «эмоциональный фон»; прототип (`toneState`) |
| R3.6-02 | Начальное состояние детерминировано: напряжение, доверие и готовность — из сложности сценария 1–5, эмоция — из группы происшествия классификатора (таблица 7.1). Звонок ДДС по карточке без сценария — «спокойно» | 3.3; 01 разд. 3.7 (уровни сложности) |
| R3.6-03 | Реплика оператора меняет состояние по правилам (таблица 7.2): успокоение и присутствие снижают напряжение и повышают доверие; обесценивание и давление — наоборот; вопрос по ещё не выясненной теме легенды повышает готовность отвечать. Короткий вопрос («Адрес?») и уточнение уже названного (подтверждение адреса) не штрафуются | прототип (`applyOperatorCues`), с исправлениями — исследование, разд. 4 |
| R3.6-04 | Состояние нельзя «накрутить» и нельзя сбросить одной репликой: каждая категория правил срабатывает не больше одного раза на реплику; успокаивающая фраза засчитывается за звонок один раз (обесценивание — каждый раз: повторное «успокойтесь» злит снова); суммарное снижение напряжения от успокоения — не больше 6. Паникующего заявителя (9) успокаивают за 3 реплики, а не за одну | разбор рисков |
| R3.6-05 | Каждое изменение состояния несёт код причины (`calming`, `invalidating`, `pressure`, `on_topic`) и фрагмент реплики, который сработал | объяснимость для преподавателя (V4) |
| R3.6-06 | Без модели (офлайн) ответ заявителя окрашивается по состоянию: при высоком напряжении — сбивчиво, с восклицаниями и повторами, при низком — ровно. **Факты легенды не меняются** | 3.3 R3.3-06 (офлайн-режим — основной) |
| R3.6-07 | С моделью состояние передаётся в промпт заявителя (`applicant_actor/v2`). Кеш ответов учитывает полосу напряжения (0–3 «спокоен», 4–7 «взволнован», 8–10 «паника»), иначе спокойный и паникующий заявитель получат один ответ | ADR-0006 |
| R3.6-08 | Ответ на реплику и просмотр звонка возвращают состояние и `id` реплики. Состояние не содержит фактов легенды, эталон по-прежнему не раскрывается | R3.3-02 |
| R3.6-09 | Снимок состояния сохраняется у каждой реплики собеседника: звук реплики и история в V4 строятся по нему, а не по текущему состоянию | ADR-0011 |
| R3.6-10 | Озвучка браузером (когда серверный синтез не настроен) следует состоянию: темп, высота и громкость реплики — по таблице 7.3. Работает офлайн. В текстовом режиме эмоция видна подписью у реплики («Заявитель · паника») — там это единственный канал интонации; шкалы обучающемуся не показываются | 01 разд. 4.1 («голос желательно»), 1.3 (изолированный контур) |

| ID | Требование | Источник |

## 4. Решения
Подробно — [ADR-0011](../docs/adr/0011-voice-emotional-caller.md) и [исследование](../docs/research/Голос_и_эмоции_заявителя.md), разд. 4. Кратко:

1. **Переносим идеи, а не сервис.** Прототип — отдельный Node-сервис: состояние и легенда у него в браузере, работает он только с OpenRouter. Встраивать его — второй бэкенд без прав и аудита и утечка легенды.
2. **Состояние — на сервере, правила — в домене.** Работает офлайн, тестируемо, объяснимо (коды причин). Модель состояние не меняет (до V5).
3. **4 параметра вместо 9.** Темп, громкость, дыхание и перебивания — функции напряжения и эмоции. Хранить их — дублирование.
4. **Отличия правил от прототипа:**
   - нет штрафа за короткую реплику (краткость — норма 112);
   - нет штрафа за уточнение уже названного: подтвердить адрес — обязанность оператора. Правило «повтор выясненного снижает доверие» было в первой версии спецификации и отвергнуто при реализации;
   - категория правил — раз на реплику, успокаивающая фраза — раз за звонок;
   - предел успокоения.
5. **Эмоция в синтез — параметром провайдера, не текстом.** Модель без поддержки инструкций не прочитает директиву вслух. Кеш по тексту не смешивает стиль и слова.
6. **Звук — отдельным ресурсом по запросу.** Текст, по которому заполняют карточку, приходит без задержки синтеза. Звук можно переслушать. Адрес своего сайта проходит CSP.
7. **Перебивание останавливает только звук.** Реплики оператора — в очереди, ответы модели не обрываются: звонок — данные автооценки.
8. **Всё выключено по умолчанию.** `tts.kind: fake`; «без рук» — переключатель. Стенд после стоп-кода и демо без ключей ведут себя как сейчас, плюс эмоции в озвучке браузера (V1).

### 7.2. Правила реакции на реплику оператора
Нормализация — `shared/text.py:search_key`, словари фраз — `domain/tone.py` (`CALMING`, `INVALIDATING`, `PRESSURE`). Категория срабатывает не больше одного раза на реплику (засчитывается первая подходящая фраза). Успокаивающая фраза, уже засчитанная в этом звонке, не срабатывает; обесценивание и давление срабатывают каждый раз. Если в реплике есть и успокоение, и обесценивание («Успокойтесь, я вас слышу»), срабатывают обе категории: напряжение не меняется, доверие тоже.

| Код | Примеры фраз | Напряжение | Доверие | Готовность |
|---|---|---|---|---|
| `calming` | «я вас слышу», «я вас понял», «оставайтесь на линии», «помощь уже едет / направлена / выехала», «мы вам поможем», «вы в безопасности», «дышите глубоко» | −2 (сумма за звонок не больше −6) | +2 | +1 |
| `invalidating` | «успокойтесь», «не кричите», «не истерите», «это неважно», «что вы орёте» | +2 | −2 | −2 |
| `pressure` | «быстрее», «отвечайте на вопрос», «мне некогда», «говорите по делу» | +1 | −1 | −1 |
| `on_topic` | вопрос с темой легенды (`domain/actors.py:topic_of`), ещё не раскрытой | 0 | 0 | +1 |

Все значения ограничены шкалой 0–10.

### 7.5. Параметры распознавания начала речи (из прототипа)
Калибровка фона — 900 мс. Порог старта — `max(абсолютный_минимум, шум × множитель + смещение)`, порог остановки — `max(минимум × 0,62, шум × 1,25 + 0,007)`.

| Профиль | Кадров для старта | Множитель шума | Смещение | Абсолютный минимум | Во время звука собеседника |
|---|---|---|---|---|---|
| высокая | 3 | 2,1 | 0,011 | 0,032 | порог × 1,45, +4 кадра |
| сбалансированная | 4 | 2,4 | 0,014 | 0,038 | порог × 1,55, +6 кадров |
| строгая | 5 | 2,8 | 0,018 | 0,045 | порог × 1,7, +8 кадров |

Минимальная длительность фразы — 420 мс, конец фразы — 680 мс тишины, пауза между фразами — 650 мс, защита после звука — 900 мс. Шум обновляется медленно (0,995 / 0,005) и только в тишине.

### 7.6. API (план)
- `POST /training/calls/{id}/replicas` → `{speaker, text, message_id, tone}`. Поля добавлены, старые клиенты их не читают.
- `GET /training/calls/{id}` → `messages[].id`, `messages[].tone` (у реплик собеседника), `tone` (текущее).
- `GET /training/calls/{id}/messages/{message_id}/audio` → `audio/mpeg` или `audio/wav`.
- `GET /training/speech` → `{enabled, tts}`. `enabled` оставлено для совместимости: оно означает распознавание.

### 7.7. Конфиг синтеза
Блок `tts` в `config/ai.yaml` и `ai.example.yaml` — локальный Speaches с Piper; в `ai.openrouter.yaml` — Gemini:
```yaml
tts:
  kind: ${TTS_KIND:-fake}              # openai_compatible — включить
  base_url: ${TTS_URL:-https://openrouter.ai/api/v1}
  api_key_env: DEMO_LLM_API_KEY        # тот же ключ OpenRouter; для локального Speaches — TTS_API_KEY, не нужен
  model: ${TTS_MODEL:-google/gemini-3.8-flash-lite-tts}
  style: ${TTS_STYLE:-google}          # google | openai | none
  response_format: ${TTS_FORMAT:-pcm}  # Gemini отдаёт сырой звук 24 кГц — сервер оборачивает его в WAV
  voice: ${TTS_VOICE:-Zephyr}
  voices:
    applicant_female: ${TTS_VOICE_FEMALE:-Kore}
    applicant_male: ${TTS_VOICE_MALE:-Charon}
    brigade: ${TTS_VOICE_BRIGADE:-Orus}
    service: ${TTS_VOICE_SERVICE:-Aoede}
  cache_ttl: 30d
  cache_mb: 64
  max_concurrency: 2
  timeout_s: 30
```
Модели Piper для Speaches: `speaches-ai/piper-ru_RU-irina-medium`, `-denis-`, `-dmitri-`, `-ruslan-` (проверено по Hugging Face 29.09.2026).
